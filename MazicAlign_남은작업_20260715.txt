[5] Step 3-4 상세: integrate/v2-mainline -> main 교체
================================================================================

  ── 무엇인가 ──
  지금 저장소(JoWooHyun/Mazic-align2)의 main 브랜치에는 "구 v1" 코드가 있고,
  실제 개발은 전부 integrate/v2-mainline 브랜치에서 이뤄져 왔다.
  Step 3-4는 v2를 main으로 승격시켜 "v2가 공식 버전"임을 저장소 차원에서
  선언하는 작업. 통합 프로젝트의 공식 마감선.

  ── 왜 필요한가 ──
  - 지금은 "main = 구버전, 진짜는 다른 브랜치"라는 어색한 상태.
    새로 오는 사람(차장님 포함)이 main을 열면 낡은 코드를 보게 됨.
  - CLAUDE.md 등 문서가 "메인라인 전환 진행 중"이라는 임시 절을 달고 있음.
    교체가 끝나야 이 임시 상태가 해소됨.

  ── 구체적으로 하는 일 ──
  1. 교체 PR 생성: integrate/v2-mainline -> main 으로 향하는 PR 하나.
     (v1 코드가 v2로 대체되는 대규모 diff — 내용은 이미 전부 검수된 것들)
  2. 전원 승인: 조우현·유승제·지현규 모두 OK 후 조우현이 머지.
  3. 기본 브랜치를 main으로 되돌림 (지금은 integrate/v2-mainline이 기본).
  4. v1 잔재 제거: v1 동결 표시(PR #30)에서 확보한 근거(v2의 v1 의존 0건)로
     v1 코드 삭제 가능 — 교체와 함께 또는 직후에.
  5. 문서 정리: CLAUDE.md의 "메인라인 전환 진행 중" 절 삭제,
     뷰어조작체계.md 등 정본 위치 일원화, 팀에 브랜치 변경 안내.
  6. 개인 저장소 아카이브 안내: admin-zero-lab, veridigital01,
     popcaron/MazicAlign 은 더 이상 쓰지 않음을 공지.

  ── 사전에 갖춰야 할 것 ──
  - 팀원 사후 확인이 끝나 있으면 이상적 (특히 유승제 PR #5·#19,
    지현규 PR #14 회귀 — 미확인 상태로 main이 되는 것 방지)
  - 실기 검증(A7/A8)은 필수는 아니나, main 승격 전에 하면 더 안전.

  ── 리스크 ──
  - 낮음. integrate/v2-mainline은 이미 30여 개 PR 검수를 거친 상태이고
    v1 의존 0건이 증명돼 있음. 교체 자체는 되돌리기도 가능(브랜치는 남음).
  - 유일한 주의점: 팀원들이 로컬에서 브랜치 기준을 main으로 바꿔야 함
    (안내문 필요 — AI가 작성 가능).

  ── 조우현이 실제로 하는 일 ──
  1. "Step 3-4 진행하자"라고 지시 -> AI가 교체 PR + 안내문 작성
  2. 유승제·지현규에게 승인 요청 (메신저)
  3. 전원 OK 확인 후 머지 버튼
