## 0. 한 줄 요약과 범위

**슬라이스 미리보기 모드(Task0 프로파일)의 가운데 2D 단면 위에, 그 층의 run.gcode 이동을 겹쳐 그린다.** 경로의 출처는 **앱이 이미 만드는 run.gcode 텍스트 그대로**(writer 를 따로 돌리거나 새 포맷을 만들지 않는다) 이고, 층 분할·좌표 해석은 **Task0 파서 이식본**(`utils/task0/task0-gcode-parser.ts`)과 커버리지 검사기의 선분 추출(`task0-coverage.ts extractTask0DepositSegments`)을 재사용한다.

- **산출물 바이트 무변경**(규칙 5): run.gcode·job.zip·PNG 는 한 바이트도 안 바뀐다. 미리보기는 **읽기 전용 소비자**다. Bambu 식 `; FEATURE:` 주석을 run.gcode 에 넣지 않는다(§6).
- 데모 가치: "슬라이서가 노즐이 어디를 지나갈지 보여 준다" + "#145 경고 층에서 **어디가** 안 덮였는지" 를 화면에서 바로 본다(지금은 경고 문구에 층 번호만).
- 범위 밖: 3D 뷰포트 안에 경로 그리기(2D 단면 패널만), 시간축 애니메이션 자동 재생(슬라이더 수동 — P3 선택), 마스크 ZIP(FDM marlin) 경로(Task0 전용).

## 2. 설계 결정

- **D1. 경로의 출처 = 마지막 run.gcode 내보내기 결과 텍스트**(F4). 내보내기 성공 시 `task0Report` 에 `gcode` 텍스트를 함께 보관하고(수명 = F5 epoch), 미리보기는 그걸 파싱한다. 층두께·모델이 바뀌면 보고와 함께 사라지고 "경로 없음 — run.gcode 를 내보내면 보입니다" 안내. **P2 에서 "경로만 계산"**(같은 워커 요청, 파일 저장 없음) 버튼을 더해 내려받기 없이도 보게 한다.
  - 기각: 미리보기 진입 때 자동으로 writer 를 돌리는 것 — 풀아치 700층은 수십 초(워커)라 진입이 느려지고 busy 상태가 꼬인다. 층 하나만 writer 로 돌리는 것 — 2재료·갇힌 층 재시도가 **이전 층 상태**(툴·리트랙트)에 걸려 파일과 다른 경로가 나올 수 있다. 파일과 **같은 것** 만 보여 준다.
- **D2. 층 분할·좌표 해석은 파서 이식본 + 선분 추출기 재사용.** `extractTask0DepositSegments` 를 일반화한 `extractTask0Moves(gcodeText)` 를 **같은 파일(`task0-coverage.ts`)에 추가**해 층마다 `{x0,y0,x1,y1,tool,kind:'deposit'|'travel', e}` 를 순서대로 돌려준다. 기존 함수는 그 결과에서 deposit 만 거르는 꼴로 바꾸되 **반환값이 글자 단위로 같아야**(검증 스크립트가 파일 A·B·C·D 로 대조 — §4). 파싱은 층 수가 수백이어도 수 ms~수십 ms 라 메인 스레드에서 1회(내보내기 직후 `useMemo`)로 충분. 1,000층 초과면 워커로 옮기는 건 P3.
- **D3. 그리기 = 단면 canvas 위에 겹친 두 번째 canvas**(`SliceSectionPane` 안, 같은 CSS 박스·`position:absolute`). 마스크 canvas 는 512 px 상한이 **동기 래스터 비용** 때문이라(F1 주석) 그대로 두고, 경로 canvas 는 선·띠만 그리므로 `CSS 크기 × devicePixelRatio` 로 더 촘촘하게 그린다. 좌표 함수 하나 `bedToSectionPx(bedX, bedY, plateW, plateD, Wpx, Hpx)` = F2∘F3 — **순수 함수로 `utils/task0/task0-path-preview.ts` 에 두고** 래스터라이저와의 일치를 스크립트로 증명(§4-1).
- **D4. 그리기 규약**(v1 F10 를 Task0 색으로 옮김):
  - 도포 = 폭 **w(mm) × scale** 의 둥근 끝 선(`lineCap:'round'`) — 실제 비드 폭. 화면 상 1 px 미만이면 1 px. 색 = 툴 색(T0 주황·T1 보라, F8), 알파 0.85.
  - 트래블 = 1 px 가는 선, 회청색 알파 0.5(리트랙트 여부는 안 구분 — P3 후보).
  - 노즐 = 진행 끝점에 빨간 점(반지름 4 px), 100 % 면 숨김(v1 과 같음).
  - 진행률 = **층 안 이동 수 기준 0~100 %**(슬라이더 1 % 단위 + 좌우 키 1 이동 단위). 기본 100 %. 층을 바꾸면 100 % 로 리셋.
  - 범례(단면 아래 캡션 줄에 추가): "주황 띠 = T0 도포 · 보라 띠 = T1 도포 · 가는 선 = 트래블 · 빨간 점 = 노즐". 2재료 캡션(기존)과 합친다.
  - 마스크 자체는 그대로(흰/재료색). 경로가 마스크를 가리지 않게 알파.
- **D5. 경고 층 표시**(#145 `failedLayers`): 층 슬라이더 레일에 경고 층 눈금(황색 점)을 찍고, 그 층에 들어가면 단면 캡션에 "⚠ 이 층은 커버리지 경고 — 파일은 냈음" + **못 덮은 성분**을 빨간 반투명 사각(성분 bbox) + 가장 깊은 점 × 표식으로 그린다. 성분은 **P2 에서 워커가 내보내기 때 계산해 결과에 실어 보낸다**(`failedLayerDetails: {layer, components: Task0CoverageComponent[]}[]`, 층당 성분 상한 16·총 상한 256 — 결과 크기 제한). 메인에서 층마다 다시 검사하는 건 기각(풀아치 층 하나 EDT 가 50~100 ms, 스크럽이 끊김).
  - 코어 변경은 **결과 객체에 필드 추가뿐**(gcode 바이트·막음/경고 판정 불변). 검사는 writer 가 이미 한 마지막 커버리지의 `uncovered` 를 가져오면 되는데, writer 는 지금 버린다(F9) → `Task0LayerStats` 에 `uncovered?` 를 남기는 작은 수정. 기존 고정 sha 검증(파일 A·B·C·D·견본 zip) 그대로 통과해야 한다.
- **D6. 2재료**: 한 층 안 T0 패스 → T1 패스 순서가 파일에 그대로 있으므로 진행률 슬라이더로 "A 먼저, B 나중" 이 보인다. 툴 전환 지점에 작은 세로 눈금을 슬라이더에 표시(선택). 겹친 곳 B 우선은 마스크 색(기존 D2)이 이미 보여 준다.
- **D7. 켜고 끄기**: 단면 패널 머리에 토글 "경로 보기"(기본 **켬**, 경로가 없으면 비활성 + 안내). 상태는 `slicePreview` 에 넣지 않고 `SliceSectionPane` 로컬(모드 이탈 시 리셋돼도 무방).
- **D8. 성능 상한**: 층 하나 이동 수는 풀아치 서포트 층에서도 수천 개. canvas 2D 로 수천 선분은 5 ms 안쪽. 진행률 스크럽마다 전부 다시 그린다(단순함 우선). 10 k 선분 넘는 층이 실측되면 오프스크린 캐시(P3).

### P1 — 경로 겹치기 (핵심, 데모 가치의 80 %)
- 코드: `task0-coverage.ts` `extractTask0Moves`(+ 기존 추출기 재정의) / `utils/task0/task0-path-preview.ts`(`bedToSectionPx`, 층 이동 → 그리기 명령 목록 순수 함수, 색·폭 상수) / `SliceSectionPane` 경로 canvas + 토글 + 진행률 슬라이더 + 캡션 / `useSliceExport` `task0Report.ok` 에 `gcode` 보관 / `ViewerV2Page` 는 props 전달 1~2줄.
- 수용 기준:
  1. Task0 프로파일에서 run.gcode 내보내기 뒤 미리보기 층을 바꾸면 그 층 경로가 마스크 위에 겹친다. 큐브(예제 20 mm): 서펜타인 행이 마스크 흰 영역 **안쪽 w/2** 에서 시작·끝난다(눈으로 — 행 끝이 흰 경계에 닿지 않음).
  2. 진행률 0 % = 경로 없음·노즐 점 (0,0) 쪽(파킹 → 첫 도포점 트래블이 첫 이동), 50 % = 절반, 100 % = 전부·노즐 숨김.
  3. 모델을 옮기거나 층두께를 바꾸면 경로가 사라지고 안내 문구. 다시 내보내면 다시 보인다.
  4. 2재료 모드 파일 D 형상(서포트 A + 판 B): T0 주황 띠가 먼저, T1 보라 띠가 뒤에 그려진다.
  5. run.gcode·job.zip 바이트 불변(기존 verify-task0-export·jobzip-export·dual-export·support-retry PASS), tsc 0·v2 lint 0.
  6. 헤드리스 `verify-task0-path-preview.mjs`(§4-1) PASS, 대조군 FAIL 증명.
- 함정: Tailwind 주석 단어(`inline`·`hidden`·`block`·`fixed`·`table`) 새로 넣지 말 것(build 해시). `SliceSectionPane` 의 래스터 상한 512 를 건드리지 말 것. `useCallback` deps(규칙 7) — `task0Report` 를 새 effect 가 읽으면 deps 에.

### P2 — 못 덮은 영역 + "경로만 계산"
- 코드: writer `Task0LayerStats.uncovered?`(실패 층만) → `task0-export` 결과 `failedLayerDetails` → 워커 메시지 타입 → `task0Report` → `SliceLayerRail` 경고 눈금 + 단면 빨간 성분 + 캡션. `useSliceExport` 에 `handleComputeTask0Paths`(= run.gcode 핸들러에서 `downloadBlob` 만 뺀 것 — 핸들러 둘이 같은 본문을 공유하도록 내부 함수로 묶는다) + `SliceSidePanel` 버튼 "경로만 계산(파일 저장 없음)".
- 수용 기준:
  1. #145 재현 픽스처(`verify-task0-support-retry` 의 서포트 발 층)에서 경고 층에 들어가면 빨간 성분 ≥ 1 개가 **마스크 흰 영역 안**에 그려지고, 다른 층에는 없다.
  2. 레일에 경고 층 눈금이 `failedLayers` 수만큼.
  3. "경로만 계산" 은 파일을 내려받지 않고 알림도 띄우지 않으며(경고는 우측 보고에만), 그 뒤 같은 입력으로 "run.gcode 만" 을 누르면 **같은 바이트**(sha 로 스크립트 확인).
  4. 고정 sha 전부 불변(결과 객체 필드만 추가).
- 결과 크기 상한(층당 16·총 256 성분) 넘으면 가장 큰 성분부터 — 검사기 `labelTask0Components` 가 이미 픽셀 수 내림차순.

## 5. 리스크·함정

- **파일 ≠ 화면 사고**: 경로는 반드시 파일과 같은 텍스트에서 나와야 한다(D1). 내보내기 **도중** 입력이 바뀐 경우 기존 `sameInputs` 가드가 보고를 버리므로 경로도 같이 버려진다 — 새 코드에서 이 가드를 우회하지 말 것.
- **좌표 반사**: STL 축 함정(CLAUDE.md)과 별개로, 단면 px 의 Y 는 world Z 와 반대(F2). 베드 Y = world Z 라 **베드 Y 가 커지면 화면 위로**. 스크립트 4-1-2 가 잡는다.
- **플레이트 치수**: Task0 프로파일에서 `plateWRef` 가 150×85 인지 출력 영역 140×75 인지 — 데모 수정 1차 ② 는 플레이트 **그림**만 바꿨으므로 150×85 가 기대값. 구현 때 확인하고, 어느 쪽이든 `bedToSectionPx` 는 래스터와 같은 W·D 를 **같은 ref 에서** 읽는다(상수 하드코딩 금지).
- **512 px 마스크 vs 촘촘한 경로**: 두 canvas 의 CSS 박스가 1 px 이라도 어긋나면 경로가 마스크에서 벗어나 보인다 — 같은 wrapper 에 `inset-0` 로 겹치고 `object-contain` 대신 **종횡비를 wrapper 가 고정**(지금 `SliceMaskPreview` 의 `max-w/max-h` 방식은 letterbox 위치가 canvas 마다 달라질 수 있음 → wrapper 가 `aspect-ratio` 를 갖도록 조정, 마스크 그리기 자체는 무변경).
- **메모리**: 풀아치 run.gcode 텍스트 수십 MB 를 상태에 보관 — 파싱 뒤 **이동 배열(Float32Array 층별)** 만 남기고 텍스트는 버린다(P1 에서 바로 그렇게).
