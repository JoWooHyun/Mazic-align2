## 2. 작업 단위와 흐름

모든 기능 작업은 다음 단위로 흐른다:

```
통합로드맵 항목 (최상단 "0. 11월 데모" 절 우선) 또는 리드 지시
   → feat/<기능명> 브랜치 (기준: origin/integrate/v2-mainline)
   → 구현 (사람 직접 또는 /dev-cycle)
   → 검증 (§4 자동 + 수동)
   → PR (조우현 확인 포인트 + 로드맵 체크박스 갱신 포함) → 조우현 머지 → 브랜치 삭제
   → 작업일지는 세션 마감 때 (/worklog)
```

- 문서만 바꾸는 작업은 `docs/<주제>-<날짜>` 브랜치로 같은 흐름을 탄다.
- 세션을 닫을 때(큰 묶음 종료)는 `docs/인수인계_YYYYMMDD.md` 를 새로 써서 다음 세션 시작점을 남긴다.

## 3. AI 개발 사이클 (/dev-cycle)

Claude Code에서 `/dev-cycle <작업 내용>` 실행 시 다음 루프가 돈다:

```
[1] 계획 (플래너 = 메인 세션)
    - CLAUDE.md, 최신 인수인계, 통합로드맵(0절), 데모 계획 §0,
      (.zip 경로면) Task0 규격서, 관련 코드 파악
    - 수정 파일 목록 + 의존성 순서 + 수용 기준(acceptance criteria) 작성
         ↓
[2] 구현 (coder 에이전트)
    - 계획과 수용 기준을 그대로 전달받아 코드 작성
         ↓
[3] 검수 (reviewer 에이전트 → 플래너 판단)
    - diff를 수용 기준·수정 규칙(CLAUDE.md 1~9) 대비 검토, §4-1 자동 검증 직접 재실행
    - 판정: PASS / FAIL(사유 + 수정 지시)
         ↓
[4] 분기
    - FAIL → 수정 지시를 coder에게 전달, [2]로 (최대 3회)
    - PASS → PR 생성 + 본문에 "조우현 확인 포인트" 작성
              → 조우현이 확인 후 머지 (= 최종 승인)
```

- 3회 반복 후에도 FAIL이면 중단하고 사람에게 판단을 넘긴다.
- 계획 단계에서 로드맵·데모 계획·규격서와 충돌이 발견되면 코딩 전에 사람에게 확인한다.
- **에이전트 운영 주의** (반복 사고):
  - 에이전트 worktree 가 v1 초기 커밋(d6b58bd)에서 시작한 사고가 두 번 있었다 → coder 에게
    "시작 시 `origin/integrate/v2-mainline` 기준인지 확인, 아니면 reset" 을 지시한다.
    worktree 는 `.claude/worktrees/`(gitignore 됨), 머지 후 `git worktree remove`.
  - coder 는 CLAUDE.md 를 고치지 않는다 — CLAUDE.md 사실 정정은 플래너가 직접 하고 PR 로 리드 승인.

## 4. 검증 체크리스트 (v2 기준 — 2026-07-08 제정, 2026-10-02 현행화)

### 4-1. 자동(헤드리스) — PR 전 필수

1. `cd frontend && npx tsc --noEmit` — **0건**(2026-10-02 정리 후 기준선 0)
2. `npm run lint` — 알려진 34건 외 **새 경고 0**
3. `npx tsx scripts/verify-<이름>.mjs` **전부** exit code 0 (10/6 기준 30종 — `ls scripts/verify-*.mjs`).
   plain `node` 금지(확장자 없는 TS import 오탐), 판정은 출력 문자열이 아니라 **exit code**. Node 20.6 이상.
4. `npm run build` 성공
5. 산출물(마스크 PNG·ZIP·G-code) 바이트가 바뀌는 수정이면 PR 에 before/after(SHA-256 또는 차이 설명) — CLAUDE.md 규칙 5
- 새 검증 스크립트는 **대조군 원칙**: 수정 전 구현·변조 구현이 실제로 FAIL 나는지 증명.

### 4-2. 수동 — `start-dev.bat`(또는 `npm run dev`) → `localhost:5173/v2`

1. **파일**: 프로젝트 생성 → "STL 열기"/드래그앤드롭/예제 모델(정육면체·구)로 STL 로드 (백엔드 없이) →
   새로고침·목록→다시 열기 후 유지(IndexedDB)
2. **편집**: 이동/회전/배율(기즈모·숫자 입력·단축키), 모델 몸통 드래그, Ctrl+Z / Ctrl+Y, 복제·복사·붙여넣기
3. **서포트**: Support 탭 자동 생성 → **모델을 옮기거나 돌리면 서포트가 따라감**(몸통 드래그·기즈모·숫자 입력 모두) →
   수동 서포트·브릿지 편집 → undo. Dental 탭 "서포트 생성(재설계)" → 목록→다시 열어도 제자리
4. **Dental(지현규)**: 브러쉬 색칠(주황) → 마진 찾기(초록 라인, 회전 추종) → 마진 안 더블클릭 채움 → 아일랜드 검출(마젠타)
5. **슬라이스 미리보기**(별도 화면 모드): 진입·"뒤로" 시 모델·시점 유지, 층 슬라이더·단면, 부피/무게/예상 시간, 미리보기 중 편집 잠금
   — 미리보기 중 Delete·Ctrl+X/V·Ctrl+Z/Y·우클릭 메뉴는 무반응이어야 정상(undo 묶음, 종합 §4-2 신규 7)
6. **내보내기**: 마스크 ZIP(`manifest.json` + 층 PNG, 진행률 + **내보내는 중 3D 뷰 조작이 끊기지 않아야 함**, 취소), G-code, STL.
   CTB 는 폐기 — 버튼이 없어야 정상. Task0 `.zip` 은 구현(2주차) 후 이 항목에 추가
7. **프로파일**: 노광·리프트 값 수정 저장 → 예상 시간 즉시 갱신 → 내보낸 파일에 반영
8. **흰 화면 방지**: 뷰어 주소 끝에 `?crash=1` → 오류 화면 + 버튼 3개("다시 시도"로 복귀)

작업이 건드린 영역의 항목은 필수, 나머지는 샘플링. 슬라이스/출력 계열 수정 시 5~7 필수.
dental 계열 수정 시 실모델(STL Sample 6개 — 이민정/홍연제) 회귀는 지현규 육안이 기준.
PR 의 "조우현 확인 포인트"는 이 목록에서 해당 항목을 골라 **무엇을 누르면 무엇이 보여야 정상인지** 문장으로 쓴다.

## 5. PR 규칙 (2026-07-08 개정 — 최종 승인·머지 = 조우현)

- **최종 검토·머지는 리드(조우현)가 한다.** AI가 만든 PR은 GitHub 규칙상 조우현이 Approve 버튼을
  누를 수 없으므로(본인 계정 authored), **머지 버튼 = 승인 행위**로 간주한다.
- PR 본문 필수 항목: 무엇을/왜, 수정 파일, AI 검수 이력(FAIL→수정 포함), 그리고
  **"조우현 확인 포인트"** — 비개발자가 실행해서 판단할 수 있는 체크리스트 (뭘 눌러보고 뭐가 보이면 OK).
- 유승제·지현규 리뷰는 **필수가 아닌 선택** — 본인 담당 영역의 설계가 크게 바뀌는 변경
  (예: BabylonScene 구조, 마진 알고리즘, IndexedDB 스키마)일 때만 리드가 지정한다.
- 개발자가 직접 올린 PR은 기존대로: 조우현이 Approve + 머지.
- 슬라이서 코어/마진 잠금 영역 변경은 반드시 PR 본문에 명시.
- **머지 후 브랜치는 바로 삭제**한다(원격 정리 관례, 2026-10-02).
