## 0. 한 줄 결론

**출력 파이프라인(슬라이스→마스크→CTB/G-code)과 치과 특화(마진·브러쉬·dental)는 이미 경쟁력이 있다.**
격차는 **① 준비 단계 편의(배치·수치입력 보강) ② 재료 절감(홀로잉) ③ 서포트 수동 편집** 세 곳에 몰려 있다.

가장 시급한 것은 기능 추가가 아니라 **이미 만든 기능의 연결**이다 — 아래 §4 "즉시 처리" 3건은 전부 신규 개발이 아니라 배선·노출 문제다.

## 3. ⚠️ 격차보다 시급 — "만들어 놨는데 연결이 안 된 것"

**신규 개발이 아니라 배선 문제다. 비용 대비 효과가 가장 크다.**

### C1. 출력영역 경고가 **Export 를 막지 않는다** 🔴
`volumeIssues` 는 배너로만 뜨고, `useSliceExport.ts` 의 4개 핸들러(ZIP/CTB/G-code/STL) 중 **누구도 읽지 않는다.** 가드는 `files.length === 0` 뿐.
→ 빨간 경고를 보면서도 **잘려 나갈 모델의 ZIP 을 정상 생성**할 수 있다. 프루사는 베드 밖이면 슬라이스를 차단한다.
**수정: `useSliceExport` 에 확인 다이얼로그 또는 차단 1곳 추가.**

### C2. `SUPPORT_DETECT_PARAM_LIMITS` 는 **죽은 코드** 🔴
9개 검출·점생성 파라미터의 한계값이 선언돼 있고 `support/index.ts` 로 re-export 까지 되는데 **읽는 컴포넌트가 0개**다.
실제로는 전부 모듈 상수이며, 예외는 `overhangAngleDeg`/`liftMm` 둘뿐 — 그것도 **일반 SupportParams 슬라이더를 빌려 쓴다**(C-3 배선).
→ **리드 결정 3("모든 값 사용자 조절")과 정면 배치.** B-22 에서 새로 만든 `verticalSpacingMm`(점 개수를 직접 좌우)도 UI 가 없어 리드가 "너무 성기다/촘촘하다" 해도 **직접 못 고친다.**
**수정: 검출 파라미터 UI 노출 (S-4d 범위였으나 앞당길 가치 큼).**

### C3. `.ctb` 내보내기 버튼이 **비활성** 🟡
인코더·핸들러 완비인데 UI 는 `disabled` + `title="ChiTuBox 강제 종료 — spec 재검토 중"`.
→ **우리 차별점(CTB)이 사용자에게 닿지 않는다.** 실기 검증 묶음(A8)과 함께 재개 필요.

### C4. 재설계 서포트 점 **미리보기 → 확정 흐름이 없다** 🟡
"검출·점생성"(저장 안 함)과 "서포트 생성"(재검출+저장)이 **독립 실행**이라, 미리 본 그 점이 확정되는 게 아니다. 점을 보고 **고친 뒤 확정**하는 경로가 없다.

### C5. STL 추가/삭제/붙여넣기가 **undo 대상이 아니다** 🟡
undo 라벨 14종은 전부 transform·서포트·브릿지. 파일을 실수로 지우면 되돌릴 수 없다.

## 4. 권고 우선순위

### 즉시 (배선·노출 — 각 1일 내외)
1. **C1 Export 가드** — 출력 실패 예방. 가장 싸고 효과 큰 안전장치
2. **C2 검출 파라미터 UI** — 리드가 서포트 밀도를 직접 조절 가능해짐. B-22 후속으로 자연스러움
3. **G7 기즈모 스냅** — Babylon `snapDistance` 속성 하나

### 단기 (1~2주)
4. **G1 자동 배치** — 치과 다중 보철의 핵심 편의. 2D 패킹으로 시작
5. **G3 안티앨리어싱** — 표면 품질 즉효. 마스크 후처리라 파이프라인 무변경
6. **G8/G9 크기 mm 입력 + 미러** — 수치패널 보강 (B-14 위에 얹기)

### 중기 (1개월+)
7. **G2 홀로잉 + 드레인홀** — 레진비 직결. manifold CSG 자산 재활용
8. **G5 서포트 수동 배치** — S-4d 범위. `kind:'manual'` 자리는 이미 예약돼 있음
9. **C4 미리보기→확정 흐름** — G5 와 함께 설계하면 자연스러움

### 보류 권장
G10 인스턴스 / G11 컷 / G13 메시수리 — 치과 시나리오에서 효용 대비 난이도가 높다.
