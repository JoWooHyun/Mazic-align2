## 0. 리드 질문에 대한 짧은 답 (전제 확인)

**Q. 프루사 프린터는 프루사 펌웨어가 프루사슬라이서 파일을 읽는 구조고, 자작 프린터도 그 펌웨어를 가져와야 파일을 쓸 수 있는 것 아닌가?**
절반만 맞습니다. 프루사슬라이서가 내는 G-code 는 "프루사 펌웨어 전용"이 아니라 **펌웨어 방언(flavor) 을 골라서** 냅니다
(Marlin / Klipper / RepRapFirmware / Prusa Buddy …). 자작 프린터는 아무 펌웨어나 올리고, 슬라이서에서 그 방언을 고르면 됩니다.
프루사 펌웨어를 가져올 필요는 없고, **"어느 펌웨어가 읽는지"에 맞춰 슬라이서가 내는 것** — 이 부분은 리드 이해가 정확합니다.

우리 경우 그 "펌웨어" 는 **Task0(vgui 후속 GUI) + Klipper** 이고, 방언 정의서가 바로 `Task0_Gcode_규격서_초안.md` 입니다.
즉 **우리는 이미 방언을 스스로 정의하는 위치**에 있고, 9/18 계획(T0-1~T0-5)이 그 방언을 MazicAlign 에 적용하는 첫 단계입니다.

**Q. 출력 파일은 .zip 에 gcode + 이미지면 되는가?**
됩니다. 선례도 있습니다: 프루사슬라이서의 레진 출력 `.sl1` 이 **정확히 ZIP(PNG 묶음 + config.ini)** 이고, 치투박스 계열 `.ctb` 만
바이너리입니다. 우리는 거기에 `run.gcode` 한 장이 더 들어가는 것뿐입니다. 전용 확장자는 만들지 않고 **`.zip` 그대로** 갑니다
(Task0 규격서 §8, PrusaSlicer 포크 계획 §4 도 동일 결론). 이름만 `<프로젝트>.job.zip` 처럼 구분.
**리드 결정(9/28): CTB 는 전혀 필요 없음. 출력물은 `.zip` 하나만.** 시판 레진기 호환은 목표가 아니며, 로드맵의 "CTB 재검토 조건"은 이 결정으로 해소.
CTB 인코더·disabled 버튼은 정리 대상(데모 후). "산출물 바이트 보존" 규칙은 마스크 PNG ZIP·G-code 에만 적용.

**Q. 층이 높아지면 테두리 도포로는 부족해지지 않나?**
Top-down 은 **플랫폼이 내려가고 노즐·블레이드·표면 높이는 항상 같습니다.** 층 번호가 도포에 영향을 주지 않습니다.
영향을 주는 것은 **그 층의 단면 면적** 입니다. 면적이 크면 테두리 한 바퀴로는 안쪽까지 레진이 못 가고, 블레이드가 끌고 가는 데도
한계가 있습니다. 그래서 "테두리 vs 채움" 은 고정 선택이 아니라 **면적·블레이드 방향에 따른 도포 패턴 설정** 이어야 합니다 (§3 D 군).
결론적으로 "테두리만" 은 소형 치아에는 충분할 수 있고, 잇몸 모델 같은 넓은 층에는 해치(줄) 채움이 필요합니다 — **실험으로 확정** (§7 캘리브레이션 잡).

## 1. 공정 한 줄 정의 (모든 설정의 기준)

```
층마다:  [슬라이서 G-code]  G1 Z(층 윗면, 절대)  →  T0 레진A 도포  →  E-r / T1 / E+r  →  T1 레진B 도포
         [Task0 삽입]       블레이드 스윕  →  LED 노광(layers/NNNN.png, exposure.json)  →  (블레이드 복귀)
```
(9/29 Task0 협의 반영: Z 는 슬라이서가 층 시작에 절대값으로 쓰고 층마다 **증가**한다. Task0 는 Z 를 넣지 않는다. 블레이드 복귀를 노광 뒤로 옮기는 역제안은 가림 확인 후. 상세 `docs/제안_Task0협의_20260929.md`)

- 슬라이서가 쓰는 것: 층 경계 마커 + 층 안 도포 경로(G1 XY E, T0/T1 전환) — **그것뿐**.
- Task0 가 하는 것: 호밍·시작/종료 시퀀스, 블레이드, LED, Z, 노즐 파킹/퍼지. 슬라이서는 이 명령을 **절대 쓰지 않음**.
- 마스크 PNG: **재료 구분 없이 층당 1장**(흰=경화). 어디에 어떤 레진이 있는지는 G-code 가 정했고, 빛은 전부 굳힘.
  → 두 레진의 노광 시간은 **한 층에 하나** — 서로 다른 값이 필요하면 큰 쪽을 쓴다 (§6 결정 5).

이 분업이 프루사에서 "슬라이서는 PRINT_START 매크로에 호밍을 위임" 하는 것과 같은 패턴입니다.

|---|---|---|---|

| | 둘레 수(perimeters) | **변형** | "테두리 도포 줄 수"(0~2). FDM 처럼 벽 정밀도 의미 없음. 마스크가 형상 담당 |

### D. 출력(잡) 설정 — 슬라이스 패널

| 필드 | 상태 |
|---|---|
| 층 두께 | 있음 |
| **도포 패턴**: 테두리 줄 수(0/1/2) + 채움(없음/줄/격자/지그재그) + 채움 간격(mm) + 각도 | **신설**. FDM `wallCount/infillPercentage` 를 의미 교체 |

## 5. 2레진 배정 — STL 을 어떻게 나누고 어떻게 인식시키나

### 5-1. 배정 단위 3단계 (쉬운 것부터, 뒤로 갈수록 선택)

| 단계 | 방법 | 근거 | 상태 |
|---|---|---|---|
| ① 역할 자동 | **서포트 = 슬롯 A(T0), 모델 = 슬롯 B(T1)** | 규격서 §7 그대로. 실기 test_2 로 층 내 전환 검증 완료(9/22) | T0-2 로 계획됨 |
| ② 파일별 지정 | 모델 목록에서 STL 마다 **A / B 드롭다운**. 씬에서 색으로 구분 | exocad 등 CAD 는 잇몸·치아를 **별도 STL** 로 내보내며 좌표가 이미 맞춰져 있음 → 재료 경계 = 파일 경계. 포크 계획의 Object→Material→Tool 과 동일 | **신설 (P4)** |
| ③ 파일 안 영역 지정 — **페인팅(기본)** | 표면 브러시로 A/B 칠함 + **마진 안 채우기**(마진 폐곡선 안쪽 표면 한 번에) + Smart fill(각도 기준 연결 면) + **관통 칠하기**(앞·뒷면 동시). 속은 §5-5 규칙으로 채움 | 프루사 MMU 페인팅과 같은 방식. 치아 하나만 B 처럼 **경계가 표면 형상(마진)인 경우**의 표준. 기존 dental 브러시(`paint-mask.ts`)에 재료 채널 추가 — 규칙 4(painted/floodfill 분리) 유지 | 데모 후 P4 |
| ④ 파일 안 영역 지정 — **분할 평면(보조)** | 모델에 평면 1개(여러 개 가능)를 놓고 이쪽 A / 저쪽 B. 층마다 평면과의 교선으로 폴리곤을 자름 | "큐브 반은 A" 처럼 **부피를 대충 나눌 때**. 뒷면 문제·속 추정 없음. 프루사 컷 도구의 뼈대 재활용 | 데모 후 P4 |

②·③이 핵심입니다. 치과 데이터는 파일이 나뉘어 오거나(②), 한 파일 안에서 치아 표면이 경계(③)입니다. ④는 큐브 같은 단순 분할용.
(9/28 논의: 처음엔 마진 2D 클리핑만 적어 뒀으나, 프루사 페인팅 화면을 리드와 함께 검토한 뒤 페인팅 기본·평면 보조로 확정.)

### 5-2. 인식·저장

- `STLFileV2` 에 `materialSlot?: 'A' | 'B'` (기본 B). IndexedDB 스키마 변경 → **협의 항목**, repo 경유(규칙 1).
- 서포트 mesh 는 항상 A. 브릿지·트렁크도 동일.
- 페인팅은 삼각형별 슬롯 배열, 분할 평면은 위치·법선 — 둘 다 STL 레코드에 붙여 저장. 프루사의 "Split triangles" 같은 삼각형 분할은 **불필요**(블레이드가 1mm 안팎 섞으므로 정밀 경계 무의미).
- 파일별 배정·페인팅·평면은 `.mzalign` 프로젝트 파일(metadata.json)에도 저장.
- **다중 파일 로드 시 상대 위치 보존 옵션 필요**: 현재 stl-loader 는 각 파일을 **AABB 중심으로 플레이트 한가운데 정렬** 합니다
  (`stl-loader.ts:115`). 잇몸+치아 세트를 그대로 올리면 각자 중앙으로 모여 **겹쳐 버립니다**. "원본 좌표 유지(세트 로드)" 옵션이 ② 의 선행 조건.

### 5-3. 한 층에 두 재료가 모두 있을 때

```
;LAYER_CHANGE  ;Z:  ;HEIGHT:
T0  (첫 층 헤더에만 명시, 이후 필요 시)
  A 폴리곤들(서포트 ∪ A 파일들) → 테두리+채움 경로
  리트랙트
T1
  B 폴리곤들(B 파일들) → 테두리+채움 경로
  (Task0: 블레이드 → LED(층 PNG = A ∪ B ∪ 서포트 전체) → Z)
```

- 한 층에 A 만 / B 만 있으면 T 라인 1개 이하. 동시 토출 없음.
- **겹침·틈 (9/29 정정 — "차집합 없음" 폐기)**: 두 STL 을 손으로 나눠 오면 겹치거나 틈이 생긴다. 층마다 2D 로 정리한다(js-clipper).
  1. 마스크 = PA ∪ PB. 겹침은 마스크에 무해. **틈**은 마스크에 슬릿이 생기므로 "재료 간 틈 x mm" 경고. g mm 이하면 닫아서(모폴로지 close) 우선 재료에 귀속시키는 옵션.
  2. **우선순위 차집합**: 목록(기본 B > A > 서포트, 사용자 재정렬) 순으로 R_B = PB, R_A = PA − R_B. 겹친 곳은 한 재료만. 둘 다 뿌리면 그 자리만 레진 2배라 블레이드 섞임이 커진다.
  3. **부스러기 제거**: offset(−ε)→offset(+ε) 로 띠 조각 제거, 남은 조각도 최소 면적(예 1mm²) 이하면 버림. 안 그러면 조각 하나 때문에 툴 체인지가 한 번 더 생긴다.
  이 정리는 T0-2 D-3("차집합 안 함")를 **대체**한다. 마스크 union 정책은 그대로.
- **경계 물리 (슬라이서가 못 고치는 것)**: 블레이드가 X 로 쓸면 경계선이 세로일 때 A 가 B 쪽으로 끌려 들어간다. 경계가 블레이드 방향과 평행하면 덜 섞인다. 슬라이서가 할 수 있는 건 셋:
  - **경계 여유(boundary inset)**: 다른 재료와 맞닿은 경계에서만 도포 영역을 d mm(0.5~1) 물림. 도포 영역 = R_m − buffer(다른 재료들, d). 외곽 inset 과 별개 값.
  - **도포량은 물리기 전 면적 기준**: E 총량 = area(R_m) × 층두께 × 배율 ÷ K 를 물린 영역의 경로에 분배. 블레이드가 펴서 원래 영역을 채우게 한다. 물린 면적으로 계산하면 경계가 항상 모자란다.
  - **순서**: 기본 B 마지막(출력물 오염 최소). 블레이드 상·하류 어느 쪽을 나중에 할지는 실험 항목이라 설정으로 열어 둠.
- **툴 체인지 비용**: 매 층 두 재료가 있으면 층마다 파킹·퍼지 1회. 파킹 왕복 10초 × 200층 = 30분 추가. 시간 추정에 "툴 체인지 횟수 × 매크로 시간"을 넣어야 하고, 매크로 시간은 Task0 측 값.

### 5-5. 속 채우기 규칙 — 표면 지정(페인팅)을 층별 A/B 폴리곤으로

프루사도 외벽만 바꾸는 게 아니라 **속을 "가장 가까운 칠해진 표면의 색"으로 채운다**(보로노이, 기본 깊이 제한 없음). 우리는 그 규칙을 그대로 쓰되 구현은 더 단순하다 — 벽·인필 분리가 필요 없고 층별 A/B 폴리곤만 있으면 된다.

1. 그 층 단면 테두리에서 칠한 삼각형이 지나는 구간에 슬롯 부여. 안 칠한 구간은 기본 슬롯(파일의 `materialSlot`).
2. 단면 안쪽 각 점은 **테두리 중 가장 가까운 구간의 슬롯**. 구현은 **래스터 거리 변환**(추천): 이미 층마다 마스크를 픽셀로 그리므로 같은 해상도로 "재료 지도"를 한 장 더 그리고, 테두리 픽셀 색을 거리 변환으로 안쪽에 전파. 벡터 보로노이는 불필요한 정밀도.
3. 옵션 "칠한 색은 깊이 n mm 까지만, 나머지는 기본"(프루사의 깊이 제한). 치아 뿌리 깊이 조절용.
4. **주의**: 앞·뒷면을 일관되게 칠해야 속 경계가 의도한 면이 된다(큐브를 앞면만 칠하면 뒷면 근처는 기본 슬롯). 관통 칠하기 옵션으로 완화. 결과는 **2색 슬라이스 미리보기로만** 확인 가능 → P7 프리뷰는 선택이 아니라 ③의 전제.

치아 하나만 칠한 잇몸 모델에 적용하면: 치관은 B, 잇몸에 가까운 쪽부터 A, 경계면은 마진 높이 근처의 돔 — 템프 레진 크라운이 모델 레진 베이스 위에 얹힌 형태.

### 5-4. 노즐 오프셋

T1 은 물리적으로 다른 자리(포크 계획 예: X+35). 방법 두 가지 — **§6 결정 4**.
- (권장) Klipper `T1` 매크로에서 `SET_GCODE_OFFSET X=… Y=…` — 슬라이서 좌표는 항상 T0 기준 한 좌표계. 캘리브레이션 값이 printer.cfg 한 곳.
- (대안) 슬라이서가 T1 경로 좌표에 오프셋 가산 — 프로파일 B 값이 진실. 프루사 방식.

## 8. 한 장 요약

> 우리는 이미 방언(Task0 규격서)을 스스로 정하는 쪽이다. 출력물은 `.zip`(gcode + PNG + json) 로 확정하고, 프루사 설정 중
> **층 두께·채움 패턴/각도·속도 3종·리트랙션·노즐 오프셋·플레이버·베드** 만 살리고 온도·팬·벽 정밀도·스커트/브림·와이프 타워·순차 출력은 버린다.
> 새로 만드는 것은 **도포 패턴(테두리+줄 채움 간격 mm, inset, 배율)·시린지 K·출력영역 오프셋/피치·재료 프로파일·파일별 A/B 배정** 이다.
> 층 안 2재료는 A(서포트·잇몸) → B(출력물) 순차, 마스크는 층당 1장, 노광은 큰 값. 겹침은 **우선순위 차집합 + 경계 여유**, 파일 안 지정은 **페인팅(기본)+분할 평면(보조)**, 속은 가장 가까운 표면 슬롯.
> CTB 는 폐기. 실기 전에 **정렬·도포량·2재료 경계 캘리브레이션 잡** 이 필수. 구현은 데모 후 P1(9/18 계획)부터, 지금은 결정 10건만.
