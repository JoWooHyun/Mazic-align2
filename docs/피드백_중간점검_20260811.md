## B. 발견 문제 — 분류와 1차 원인

### B-1. 생성 후 모델 이동/회전 시 서포트가 따라가며 기울어짐 (심각·설계 판단 필요)

- 현상: STL을 회전/이동하면 서포트가 같이 움직여 기둥이 기울고 공중에 뜸. 화살표(기즈모) 드래그 시 갑자기 점프.
- 원인: `useSupportMeshSync`가 `mesh.parent = stlMesh`로 STL transform을 자동 추종(stl-local 저장).
  PR #39 알려진 한계("저장 후 모델 이동 시 재생성 필요")의 실물 확인.
- 필요 결정: 모델 transform 시 재설계 서포트 처리 정책 — CHITUBOX식 "무효화(경고+삭제)" vs 자동 재생성.

### B-2. 일정 시간 뒤 서포트가 움직이거나 다시 생성됨 (버그 의심·진단 필요)

- 현상: 어떤 메커니즘에 의해 잠시 후 서포트가 이동하거나 재생성됨.
- 1차 추정: `useSupportMeshSync`의 rebuild key가 "STL local 좌표+params" 기준인데,
  stl-local이 아닌 점(구 좌표계 점)은 매 실행마다 inv(world) 변환값으로 key가 바뀌어
  STL 이동 후 effect 재실행 시 재생성될 수 있음. headless/뷰어 재현으로 확정 필요.

### B-3. 재설계 서포트가 과다 생성 (약 1,300개) (기본값·검출 문제)

- 원인 후보 2가지(중첩):
  1. 오버행 검출이 검출각 미적용 층-겹침 근사(S-4a 알려진 TODO) → 과검출.
  2. 점 간격 기본값 `fillSpacingMm=3.0` / `overhangSpacingMm=3.0` 고정
     (`support/utils/defaults.ts`) — 조절 UI는 S-4d 예정이라 현재 사용자가 못 바꿈.
- 영향: 출력물 품질 + S-4b-2 충돌회피(기둥당 광선 8~16개)가 1,300개면 연산 폭발.
  **S-4b-2 착수 전 완화 권장.**

### B-4. 재설계 디버그 표시(마젠타/파랑/주황 점)가 모델을 안 따라가고 잔류

- 원인: 디버그 오버레이는 world 좌표로 직접 찍고 parent 없음(`redesign-detect-actions.ts`).
- "표시 지우기"로 제거되는 것은 정상. 생성 시 자동 정리 여부는 기존 보류 항목 — 이번에 정리 권장.

### B-5. 정상(버그 아님)으로 판정된 관찰

- 재설계 전 자동생성(trunk)과 재설계 생성의 모양이 다름 → 별도 알고리즘이라 정상.
- (구 서포트) STL을 올리면 길어지고 내리면 짧아짐 → trunk는 base가 플레이트(Y=0) 고정이라 의도된 동작.

### B-6. (전 세션 접수) 뷰포트 오버레이 글자가 드래그에 긁힘

- 원인: ViewControls 등 오버레이에 `select-none` 미적용. 소형 CSS 수정.
- 같이 접수된 축 표기 문제(Z가 높이가 아님, Babylon Y-up 노출)는 별도 항목 — 표시용 Y↔Z 스왑 방향.
