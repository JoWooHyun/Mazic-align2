# 리팩토링 — LLM 친화 구조 분리 (2026-07-20)

- 작성: 2026-07-20 (AI, 리드 지시)
- 배경: AI 세션이 큰 파일을 읽을 때 토큰 소모가 과도함. 500줄 이상 갓파일 3개를 **단일 책임 원칙(SRP)** 에 따라
  작은 파일로 분리해, 이후 AI 작업이 "필요한 조각만 읽는" 구조로 전환.
- 원칙: **행동 불변(behavior-preserving)** — 로직·수치·문자열·순서를 바꾸지 않고 순수 이동+분할만 수행.
- 진행 방식: WORKFLOW의 AI 사이클 (플래너 계획 → coder 구현 → reviewer 독립 검수 → PASS 시 커밋).

## 5. 유지해야 하는 불변식 (다음 작업자·AI 필독)

BabylonScene 분리에서 **깨지면 안 되는 것들** — 코드 주석에도 명시돼 있음:

1. **훅 호출 순서 = 원본 effect 선언 순서** (bootstrap → fileMesh → supportMesh → selection →
   slicePreview → bridgeViz → editMode → **dentalBrush** → [10/22 현행] buildVolumeCheck → alignFloorHover 마지막 — §4 호출 순서 표). React는 unmount cleanup을 등록
   순서대로 실행하며, bootstrap cleanup이 먼저 `isUnmountingRef=true`를 세팅해야 brush cleanup이
   pending 무효화를 "즉시 실행"이 아닌 "타이머 정리"로 처리한다. **훅 순서를 바꾸면 안 된다.**
2. **dispose 순서** (`dispose-scene.ts`): isUnmounting 플래그 → … → `scene.dispose()` →
   `engine.dispose()` 맨 마지막. 순서 재배열 금지.
3. 이벤트 짝: canvas wheel은 `{capture:true}`로 등록·해제 모두, brush 포인터 옵저버는 같은 effect
   내 명시 remove, 더블탭·클릭픽 옵저버는 bootstrap에 남아 `scene.dispose()`가 정리.
4. gizmo 드래그 중 `setParent(mesh)` ↔ `setParent(null)` 짝, manifold wasm `delete()` 짝,
   dental-brush 이탈 시 카메라 버튼 `[0,1,2]` 원복.
   - (2026-10-07 사고 방지 2차 C3·C7) STL manifold 캐시는 모델 삭제·취소된 로드·같은 id 재등록 때
     `releaseStlManifold`, **씬 정리 때 `releaseAllStlManifolds`**(dispose-scene 의 STL 메시 단계 안,
     `meshMapRef.clear()` 직후 — 새 단계 아님). STL 메시 해제는 `disposeStlMesh`(전용 머티리얼만 해제) —
     STL 에 `dispose(false, true)` 금지: 자식의 브릿지·stl-local 서포트가 쓰는 **공유** 서포트 머티리얼까지
     재귀로 지운다. 헬퍼 `components/babylon/resource-release.ts`, 검증 `verify-safety2.mjs`.
5. `pendingInvalidationsRef`는 컴포넌트 레벨(SceneCtx) 소유 — 훅 로컬로 내리면 B3 레이스 회귀.
