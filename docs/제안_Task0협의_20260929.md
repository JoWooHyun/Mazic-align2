## 0. 분업 원칙 (이미 합의된 것 — 재확인만)

```
층마다:  [슬라이서 run.gcode]  T0 레진A 도포  →  T1 레진B 도포
         [Task0 삽입]          블레이드 스윕  →  LED 노광(layers/NNNN.png)  →  Z 하강
```

- 슬라이서는 **층 경계 마커 + 층 안 도포 경로**만 쓴다. 호밍·블레이드·LED·Z·파킹·퍼지는 **한 줄도 쓰지 않는다**(규격서 §4 PRINT_START 위임 패턴).
- 마스크는 재료 구분 없이 **층당 1장**. 빛은 전부 굳힌다. 어디에 어떤 레진이 있는지는 G-code 가 정한다.
- 이 원칙에 이견 없으면 아래는 전부 이 위에 얹는 얘기다.

> **Task0 회신 (2026-09-29, 조우현)** — 원칙 §0 동의. 아래 "Task0 의견:"은 Task0 코드(printer.cfg, motor_controller, parse_gcode_dryrun, gcode_parser, print_worker) 기준으로 적었다. 【확인 필요】는 하드웨어 실측·담당자 확인 전 잠정값.
>
> **전제 3가지 먼저:**
> 1. **용어 — "Z 하강"(이 문서) = "Z 상승"(Task0 문서) = 같은 동작.** 수치로 Z는 층마다 layerHeight 만큼 **증가**한다(엔드스톱 0 → 최대 2000). 앞으로 "Z 다음 층 이동"으로 쓰고 부호는 증가로 통일.
> 2. **Task0 구현 현황(정직하게):** 실기 검증된 건 **드라이런 경로**(parse_gcode_dryrun → 층 블록 전송 → 블레이드(G-code 내) → LED)뿐이다. job.zip 로드·manifest/exposure.json 해석·층별 PNG 투사가 붙은 **실출력 워커(Task0 Step 4~5)는 미구현**. 현 ZIP 검증기는 옛 MAZIC-CERA 전용(`preview_cropping.png`, `;machineX:124.8` 요구)이라 MazicAlign zip을 거부한다 → Task0가 `manifest.json` 유무로 분기하는 새 로더를 만든다. **슬라이서는 옛 검증기를 맞추려 하지 말 것.**
> 3. §0 그림의 `[Task0 삽입] … Z 하강`은 **삭제 제안** — Z는 슬라이서가 층 시작에 `G1 Z` 절대값으로 쓰고 Task0는 Z를 넣지 않는다(§2-7 참조). 즉 Task0 삽입은 `블레이드 → LED`만.

## 2. Task0 에 부탁·제안하는 것

각 항목에 우리 제안과 이유를 적었다. 다른 게 맞으면 그렇게 하자.

### 2-1. T1 노즐 오프셋은 Klipper `T1` 매크로에서 (`SET_GCODE_OFFSET`)
- **제안**: 슬라이서는 항상 **T0 기준 한 좌표계**로만 쓴다. `T1` 매크로가 `SET_GCODE_OFFSET X=<dx> Y=<dy>`, `T0` 매크로가 `X=0 Y=0` 으로 되돌린다.
- **이유**: 오프셋 실측값이 `printer.cfg` 한 곳에만 있으면 캘리브레이션 후 슬라이서 프로파일을 또 고칠 일이 없다. 프루사 방식(슬라이서 가산)도 되지만 진실이 두 곳이 된다.
- 만약 Task0 가 슬라이서 가산을 원하면 우리 프로파일에 `nozzleOffset` 을 두겠다. 어느 쪽이든 **한 곳만**.
- Task0 의견: **동의 — Klipper 매크로에서 `SET_GCODE_OFFSET`. 슬라이서 프로파일에 `nozzleOffset` 두지 말 것.**
  - 구현: `[gcode_macro _TOOL_OFFSET]` 에 `variable_t1_x/t1_y/t1_z` 한 곳 → `T1` = `ACTIVATE_EXTRUDER EXTRUDER=extruder1` + `SET_GCODE_OFFSET X={x} Y={y} Z={z}`, `T0` = `ACTIVATE_EXTRUDER EXTRUDER=extruder` + `SET_GCODE_OFFSET X=0 Y=0 Z=0`. `MOVE=1` 없이 적용(다음 G1부터 반영, 즉시 물리 이동 없음).
  - **Z 오프셋도 매크로가 맡는다.** 시린지 노즐 2개의 높이차는 반드시 생긴다 → 슬라이서는 X/Y/Z 모두 T0 기준 한 좌표계.
  - 현재 매크로는 `ACTIVATE_EXTRUDER` 한 줄(오프셋 0). 정렬 잡(S8①) 결과로 값 기입.

### 2-2. 시간 추정용 상수 3개
- 툴 체인지 1회(파킹 왕복 + 퍼지) 소요 초, 층당 블레이드 스윕 초(왕복이면 왕복 기준), 층당 LED 노광 외 오버헤드 초(Z 하강·안정 대기).
- **이유**: 큐브 반갈라기처럼 매 층 두 재료면 툴 체인지가 층 수만큼 생긴다. 10초 × 200층 = 30분이라 추정에서 빠지면 안 된다.
- 실측 전이면 대략값이라도. 우리는 프로파일 필드로 두고 나중에 갱신.
- Task0 의견: 코드 기준 잠정값(실측 후 갱신):
  | 상수 | 잠정값 | 근거 |
  |---|---|---|
  | toolChangeSec | **0.5** | 현 T 매크로 = ACTIVATE_EXTRUDER(+오프셋)만, 파킹/퍼지 없음. Moonraker 왕복 포함. 퍼지 도입 시 5~15로 갱신 |
  | bladeSec (층당) | **10** | 기본 스윕 100 mm @ 20 mm/s **왕복**(5+5) + 가감속(100 mm/s²) 여유. test_2는 80 mm 사용 |
  | layerOverheadSec | **2** | Z 층 이동 ≈0 + M400 왕복·완료 폴링 ~0.5 + LED ON/OFF 시리얼 ~0.3 + 마스크 표시 ~0.2 + 여유. LED 노광 시간은 별도(exposure.json) |
  - 블레이드 시퀀스가 §2-5 제안(스윕→LED→복귀)으로 바뀌면 bladeSec은 노광과 겹치는 복귀분(5)을 빼서 계산.

### 2-3. 출력영역 오프셋·픽셀 피치 실측 (정렬 캘리브레이션 잡)
- 필요한 값: 베드 원점(엔드스톱 0,0)에서 프로젝터 투사 영역 좌하단까지 X/Y mm, 투사 폭 ÷ 1920 = 피치 µm, **마스크 Y 축이 위인지 아래인지**(우리 래스터는 Z+ 가 화면 위. G-code 는 Y+ 가 안쪽. 실기에서 뒤집혔는지 미검증 — 로드맵 A7).
- **제안**: 우리가 S8 ① 정렬 잡(십자 마스크 5점 + 같은 자리 T0 도포 점, T1 로 반복)을 zip 으로 만들어 주면 Task0 가 돌려서 경화 십자와 도포 자국의 어긋남을 재 준다. 한 번에 오프셋·피치·Y 뒤집힘·T1 오프셋이 다 나온다.
- 그 전에 Task0 쪽에서 대략값(자로 잰 값)을 주면 프로파일 초기값으로 넣겠다.
- Task0 의견: **정렬 잡 방식 동의.** Task0가 마스크를 다루는 방식을 먼저 확정한다:
  - Task0는 PNG를 **1920×1080 전체 화면에 그대로** 띄운다(KeepAspectRatio 스케일만, 크롭/오프셋/소프트웨어 플립 **없음**). 오프셋·피치는 슬라이서 래스터가 반영하는 값이고 Task0는 표시용으로만 읽는다.
  - **플립은 Task0가 광원 하드웨어 설정으로 맞춘다**(DF10 `set_flip` H/V — NVR2+도 같은 API). 따라서 **슬라이서 래스터 규약은 고정**: 열 0 = X 최소, 행 0(위) = Y 최대 (위에서 내려다본 평면도, Y+ 가 화면 위). 정렬 잡에서 뒤집힘이 나오면 Task0 플립 설정 한 줄로 잡는다 — 슬라이서 수정 없음.
  - 자로 잰 초기값: 【확인 필요 — 실측: 엔드스톱 (0,0)→투사영역 좌하단 X/Y mm, 투사 폭 mm】. 피치 초기값 = 투사 폭 ÷ 1920. 실측 전엔 프로파일에 `offsetMm: [0,0]`, `pixelPitchUm: 78.1`(150 mm/1920 가정) 넣어도 됨 — 정렬 잡이 어차피 덮어씀.

### 2-4. 잉여 레진의 행방
- 블레이드가 밀어낸 남는 레진이 **회수되나, 베드 밖으로 떨어지나, 그 자리에 쌓이나**?
- **이유**: 우리 "과충전 배율"(부족 방지용 1.0~2.0)을 넉넉히 잡아도 되는지가 여기에 달렸다. 회수되면 넉넉히, 쌓이면 정밀하게.
- Task0 의견: 【확인 필요 — 하드웨어 담당 답변】 코드상 잉여 레진 처리 로직은 없다(블레이드는 단순 왕복). 선택지: (a) 베드 끝 회수통으로 밀어냄 (b) 베드 밖으로 떨어짐 (c) 끝단에 쌓임. 답이 나오기 전 잠정 권고: **과충전 배율 1.0~1.2로 보수적으로**, 정렬 잡·도포량 잡(S8②)에서 실측 후 상향.

### 2-5. 블레이드 진행 방향과 경계 섞임
- 블레이드가 X 로 쓸면 세로 경계에서 A 가 B 쪽으로 끌려 들어간다. 우리는 경계 여유·순서로 완화하지만 물리는 못 고친다.
- 묻는 것: 블레이드는 **편도인가 왕복인가**, 시작 방향은 −X→+X 인가? 왕복이면 경계 섞임이 양방향이라 "상류 재료를 나중에" 같은 순서 전략이 무의미해진다.
- S8 ③ 경계 잡으로 섞임 띠 폭을 실측하자. 그 값이 "2재료 경계 최소 간격" 스펙이 된다.
- Task0 의견: 코드 기준 확정 사실 + 시퀀스 역제안:
  - **블레이드는 X/Y와 독립된 별도 축**(`manual_stepper blade`, 소프트 원점). 현재 **왕복**: `MOVE=100`(스윕) → `MOVE=0`(복귀), 같은 속도 20 mm/s, **리프트 없음 → 복귀 패스도 레진에 닿는다.**
  - 물리 진행 방향(−X→+X인지, Y 방향인지): 【확인 필요 — 사용자】.
  - **Task0 역제안: 층 시퀀스를 `스윕 → LED 노광 → 복귀`로 바꾼다.** 복귀 패스가 **경화된 층 위**를 지나므로 복귀 방향 섞임이 없어져 사실상 편도가 된다 → "상류 재료 나중에" 순서 전략이 유효해진다. 조건: 스윕 끝 위치에서 블레이드가 투사광을 가리지 않아야 함 【확인 필요】. 가리면 현행 왕복 유지하고 S8③으로 섬임 폭 실측.
  - 스윕 거리(기본 100 mm)·속도(기본 20, 실험 범위 5~40 mm/s)는 Task0 GUI 설정. 슬라이서는 관여 안 함.

### 2-6. 층 안 T 전환 시 리트랙션(슬라이서) vs 퍼지(Task0) 분담 — 규격서 미정 4
- **제안**: 슬라이서는 전환 직전 리트랙트 1회(`E-r`, r 은 재료 프로파일 값)만. 파킹에서의 퍼지·와이프는 T 매크로가 전담. 슬라이서는 퍼지량을 모른다.
- 되돌아오는 노즐의 프라이밍(퍼지 후 첫 도포까지 빈 구간)이 문제면, 매크로에서 `E+r` 로 언리트랙트까지 해 주는 게 깔끔하다. 아니면 슬라이서가 T 라인 뒤에 `E+r` 을 쓴다 — **누가 쓰는지만 정하자**(둘 다 쓰면 2배).
- Task0 의견: **부분 동의 + 역제안: 리트랙트(`E-r`)와 언리트랙트(`E+r`) 둘 다 슬라이서, 매크로는 파킹+퍼지만.**
  - 이유: r은 재료 프로파일 값(슬라이서 소유). 매크로가 언리트랙트하면 r을 printer.cfg에도 둬야 해서 §2-1에서 세운 "진실은 한 곳" 원칙과 충돌.
  - 가능한 근거: E는 M83 상대 모드 → 매크로의 퍼지 `G1 E{p}`는 슬라이서 E 흐름을 건드리지 않는다. 매크로는 "리트랙트 상태를 순변화 없이 끝낸다"만 지키면 된다.
  - 이 패턴은 test_2.gcode(`G1 E-20` → `T1` → `G1 E20`)로 **실기 검증 완료**.
  - 현 단계: 매크로에 파킹/퍼지 없음. 도입 시점은 미정 4 실험 후(§3-2). 슬라이서는 지금부터 `E-r` / `T1` / `E+r` 순서로 쓰면 이후 매크로 변경에 영향 없음.

### 2-7. 파서 관련 확인 4건 (9/18 계획 §5 되묻기)
- `;HEIGHT:` 는 층 두께로 이해. 첫 층도 같은 값이면 되는지.
- `; EXECUTABLE_BLOCK_END` 는 test_demo.gcode 에만 있고 규격서엔 없음 — 필요한가.
- 미지 명령을 **조용히** 버리는 현 파서에서 `G92` 처럼 버리면 위험한 명령이 또 없는지(`M400` 통과는 확인됨). 화이트리스트 밖은 **경고 로그**를 내 주면 우리 검증기와 맞출 수 있다.
- 층 시작의 절대 `G1 Z{z}` 1줄: 우리는 찍을 생각(멱등). Task0 가 Z 를 자체 계산해 보내면 빼겠다 — 어느 쪽?
- Task0 의견:
  1. **`;HEIGHT:` 첫 층 같은 값 — OK.** 현 파서는 `;Z:`/`;HEIGHT:` 모두 **읽지 않는다**(주석은 전부 버림). v0.2에서 `;Z:`만 검증용으로 읽을 예정(manifest `layerHeightMm × (N+1)` 대조, 허용오차 ±0.001). HEIGHT는 정보용.
  2. **`; EXECUTABLE_BLOCK_END` 불필요.** 써도 무해(주석). 단 **현 파서는 END에서 멈추지 않는다** → END 뒤에 명령 두지 말 것. v0.2에서 END 인식 추가.
  3. **미지 명령: 현재 조용히 버림(로그 없음).** 규격서 §3 문구("경고 로그 후 스킵")와 코드가 불일치 — v0.2에서 경고 로그 추가하고 검증기(S10)와 문구를 맞춘다. 위험 명령 점검: `G92` 통과 ✓, `M400` ✓, `M82/M83` ✓, `T0/T1` ✓. **버려지는 것 중 주의**: `G10/G11`(펌웨어 리트랙트) → **쓰지 말 것**(리트랙트는 `G1 E-r`로), `G4`(대기) 버림, `M204`/`SET_VELOCITY_LIMIT` 버림(속도는 Task0 관리), **F만 있는 `G1 F1800`은 버림** → 속도는 이동 줄에 같이. 전체 규칙은 **부록 A**.
  4. **`G1 Z{z}` 유지 — 슬라이서가 쓴다. Task0는 Z를 넣지 않는다.** 근거: test_2 구조(층 시작 절대 `G1 Z`)로 실기 검증됨, Task0가 다음 층 Z를 계산할 필요가 없어짐. Task0가 나중에 노광 전후 리프트/필을 넣더라도 층 Z로 되돌린 뒤 다음 블록을 보내므로 슬라이서의 절대 Z는 계속 유효. (§0 그림의 "[Task0 삽입] Z 하강" 삭제 요청)

### 2-8. 노광은 층당 1회 — 두 재료 노광 시간이 다르면 큰 값
- 마스크가 층당 1장이라 LED 는 층당 1회. 재료 A/B 의 노광 시간이 다르면 슬라이서가 **큰 값**을 exposure.json 에 쓰고 UI 에 경고.

## 3. 같이 정할 것 (규격서 v0.2 항목)

### 3-1. job.zip 규격 (규격서 §8 확정) — 우리 제안

```
<프로젝트명>.job.zip
├── run.gcode              Task0 플레이버 G-code (규격서 §2~§7)
├── manifest.json          메타 (아래)
├── exposure.json          층별 노광 (아래)
├── preview.png            썸네일 (Task0 GUI 목록용, 400×300 권장)
└── layers/
    ├── 0000.png           ← 0-based, 4자리. 첫 층 = 0000
    ├── 0001.png
    └── …
```

- **PNG 형식**: 1920×1080, **8-bit grayscale**(지금은 0/255 만 씀). 이유: 나중에 안티앨리어싱을 넣어도 포맷이 안 바뀐다. 1bpp 를 원하면 그렇게 하겠다 — 파일당 크기 8배 차이라 Task0 읽기 속도 기준으로 정하자.
- **층 번호**: 규격서 §8 은 `layer_%04d.png`, PrusaSlicer 포크 계획은 `0000.png`, 우리 현 마스크 ZIP 은 `layer_0001.png`(1-based). **세 가지가 다르다.** 제안은 `0000.png` 0-based — `;LAYER_CHANGE` 순서와 1:1 이고 접두어 없이 정렬된다.
- **G-code ↔ PNG 대응**: N 번째 `;LAYER_CHANGE` 뒤 도포가 끝나고 Task0 가 노광할 때 `layers/NNNN.png` 를 쓴다(N 은 0-based). `;Z:` 값과 manifest 의 `layerHeightMm × (N+1)` 이 일치해야 한다 — 검증기가 확인.

**manifest.json 제안**
```json
{
  "format": "mazicalign-job", "version": 1,
  "generator": "MazicAlign v2 <버전>", "generatedAt": "<ISO>",
  "layerCount": 1200, "layerHeightMm": 0.05,
  "projector": { "widthPx": 1920, "heightPx": 1080, "pixelPitchUm": <실측>, "offsetMm": [<x>, <y>] },
  "bed": { "widthMm": 150, "depthMm": 85 },
  "materials": [
    { "slot": "A", "tool": "T0", "name": "모델레진", "exposureSec": 2.5, "bottomExposureSec": 30, "retractMm": 1.0 },
    { "slot": "B", "tool": "T1", "name": "템프레진", "exposureSec": 3.0, "bottomExposureSec": 30, "retractMm": 1.0 }
  ],
  "dualMaterial": true,
  "toolChangeCount": 1200,
  "estimate": { "depositSec": 0, "travelSec": 0, "toolChangeSec": 0, "layerOverheadSec": 0, "exposureSec": 0, "totalSec": 0 },
  "hints": { "blade": null, "ledPower": null }
}
```
- `hints` 는 슬라이서가 **요청**만 하고 Task0 GUI 설정이 우선. 필요 없으면 빼자.
- `materials` 가 1개면 단일 모드(규격서 §8 의 `material_info.json` 을 manifest 안으로 합친 형태 — 파일 하나 줄이자는 제안).

**exposure.json 제안** — 현재 우리 마스크 ZIP manifest 의 `exposureSecByLayer` 를 그대로 분리
```json
{ "layerHeightMm": 0.05, "bottomLayerCount": 5, "transitionLayerCount": 0,
  "exposureSecByLayer": [30, 30, 30, 30, 30, 2.5, 2.5, …] }
```
- 층별 배열이라 Task0 는 계산 없이 인덱스로 읽으면 된다. 배열 길이 = layerCount.
- Task0 의견: **전부 동의, 세부 확정:**
  - **`layers/0000.png` 0-based 채택** → 규격서 §8 `layer_%04d.png` 폐기. 현 Task0 이미지 로더(파일명 숫자 정렬, 0-based 인덱스)와 연속성 검사(`^\d+\.png$`)에 그대로 맞는다. 세 가지 중 이걸로 통일.
  - **PNG 8-bit grayscale 동의.** CM4에서 1920×1080 PNG 디코드는 수십 ms — 1bpp 불필요. 값 해석: 0=미노광, 255=노광, 중간값은 그대로 투사(안티앨리어싱 허용).
  - **material_info.json → manifest 병합 동의.** `hints`는 optional로 유지, Task0 GUI 설정 우선(없으면 무시).
  - **Task0가 manifest에서 실제로 읽는 것**: `format`/`version`(분기), `layerCount`, `layerHeightMm`, `bed`(150×85 초과면 로드 거부), `projector.widthPx/heightPx`(1920×1080 아니면 거부), `materials[].tool/name/exposureSec`(GUI 표시), `dualMaterial`, `estimate.totalSec`(진행률), `toolChangeCount`(표시). `projector.pixelPitchUm/offsetMm`는 **표시만**(정렬은 슬라이서 래스터 책임, §2-3).
  - **exposure.json 동의.** Task0는 `exposureSecByLayer[N]`만 쓴다. `bottomLayerCount/transitionLayerCount`는 정보용.
  - **Task0 새 로더가 거부하는 조건(= 검증기 S10과 맞출 것)**: run.gcode 없음 / manifest.json 없음 또는 version≠1 / `;LAYER_CHANGE` 개수 ≠ layerCount ≠ PNG 개수 / PNG 번호 불연속 / 해상도·베드 불일치 / exposure 배열 길이 ≠ layerCount / `;Z:` vs `layerHeightMm×(N+1)` 불일치(±0.001).
  - `preview.png` 400×300 OK. 옛 검증기의 `preview_cropping.png`·`;machineX:` 요구는 새 로더에서 제거.

### 5-2. 새 발견 — 층 번호·Z 규약을 마스크와 G-code 가 **다르게** 쓰고 있다 (합의 필요 ★)

Task0 거부 조건 "`;LAYER_CHANGE` 개수 = layerCount = PNG 개수, `;Z:` = layerHeightMm × (N+1)" 을 우리 현 코드에 대보니 **안 맞는다**:

| | 현 마스크 ZIP (`slice-batch.ts`) | 현 FDM G-code (`fdm-gcode.ts`) |
|---|---|---|
| 층 수 | ceil(topY / lh) | **ceil(높이 / lh) + 1** |
| 층 N 의 단면 높이 | (N + 0.5) × lh (중앙 샘플링) | **N × lh + ε** (바닥 샘플링) |
| 층 N 의 Z 표기 | — | **N × lh** (첫 층 Z = 0) |

즉 같은 모델로 뽑아도 PNG 가 G-code 보다 한 층 적고, `;Z:` 는 Task0 기대값보다 한 층 낮으며, 층 N 의 도포 폴리곤과 마스크 PNG 가 **다른 높이의 단면**이다. FDM 단독일 땐 문제가 없었지만(마스크와 짝지을 일이 없었음), 하이브리드에선 층마다 "도포 영역 = 경화 영역" 이어야 하므로 **하나로 통일**해야 한다.

**우리 제안 (task0 플레이버 한정 — marlin 플레이버는 바이트 보존):**
- 층 수 = ceil(topY / lh) — 마스크 규약. topY 는 플레이트 0 기준 씬 최고점(서포트 포함).
- 층 N 의 단면 = (N + 0.5) × lh 에서 자른 것 — **마스크와 동일 평면**. 도포 폴리곤과 PNG 가 같은 단면에서 나온다.
- `;Z:` = `G1 Z` = (N + 1) × lh — Task0 기대값. 물리 의미: 이 층의 **윗면** 높이(도포 후 블레이드가 깎는 면).
- `;HEIGHT:` = lh.
- **Task0 확인 요청**: `G1 Z(N+1)×lh` 를 "층 윗면" 으로 해석하는 게 맞는지 — 즉 노즐·블레이드 기준 높이가 Z 축 좌표계에서 어디인지(플랫폼 위치 Z 와 층 윗면의 관계). 바닥 N×lh 를 기대한다면 우리는 그쪽으로 맞춘다. **한 줄만 답해 주면 됨: 층 N 의 `G1 Z` = (N+1)×lh 인지 N×lh 인지.**

## 6. Task0 재회신 (2026-09-29, 2차) — §5-2 답 + 후속

### 6-1. §5-2 답: **층 N(0-based)의 `G1 Z` = `;Z:` = (N+1) × lh. 첫 층 Z = lh (0 아님).**

- **물리 의미**: Task0 Z축 = 빌드 플랫폼(`stepper_z`). Z 수치가 커지면 플랫폼이 블레이드/노즐에서 **멀어진다**(내려간다). Z 좌표 = "플랫폼 윗면이 블레이드 평면 아래로 내려간 깊이" = 그 층까지 쌓인 총 두께 = **층 N의 윗면 높이**. 층 N을 도포하려면 이전 층 윗면이 블레이드 평면보다 lh 만큼 아래 있어야 하므로 플랫폼 깊이 = (N+1)×lh. 노즐은 블레이드 평면 위 고정 간격(하드웨어)에서 넉넉히 도포하고, 블레이드가 평면으로 깎는다 → 층 윗면 = 블레이드 평면.
- **근거**: Task0 실출력 워커의 현 식 `z = z_offset + (layer_idx + 1) × layerHeight` (`workers/print_worker.py:457`). 표준 FDM 슬라이서(Orca/Prusa)도 첫 층 `;Z:` = 층두께(해부노트 `;Z:0.4 / ;HEIGHT:0.2` = 2층).
- **플랫폼 영점(z_offset)은 Task0가 처리한다 — 슬라이서 Z는 순수 (N+1)×lh.** 출력 시작 시 Task0가 `SET_GCODE_OFFSET Z=<플랫폼 영점>`을 걸어 "플랫폼 윗면 = 블레이드 평면"인 실제 좌표를 0에 맞춘다. 슬라이서는 기계 캘리브레이션 값을 몰라도 된다.
  - 이에 맞춰 §2-1의 T1 Z 오프셋은 **덧셈**으로: `_TOOL_OFFSET` 변수에 `bed_z`(영점)와 `t1_z`. `T1` = `SET_GCODE_OFFSET X={t1_x} Y={t1_y} Z={bed_z + t1_z}`, `T0` = `X=0 Y=0 Z={bed_z}` (절대값으로 써서 중복 적용 방지). Task0 내부 사항, 슬라이서 무관.
- **§5-2 제안 3줄 전부 수용**: 층 수 = ceil(topY / lh) / 층 N 단면 = (N+0.5)×lh 에서 자름(마스크와 동일 평면) / `;HEIGHT:` = lh.
- **검증기(S10) 기대값 정리**: 층 0 → `;Z:` = `G1 Z` = lh, `layers/0000.png` = 0.5·lh 단면, `exposureSecByLayer[0]`. 층 N → (N+1)·lh, `NNNN.png`, `[N]`. 프리앰블 블록엔 `G1 Z` 없음(있어도 무해). Task0 거부 조건의 `;Z:` 대조식은 그대로 `layerHeightMm × (N+1)` ±0.001.
- 참고(Task0 소관 아님): 표준 FDM도 (N+1)×lh 라서 marlin 플레이버의 "첫 층 Z=0"은 실제 FDM에선 노즐이 베드에 닿는 값이다. 바이트 보존 결정은 존중 — 정보만.

## 12. Task0 회신 (2026-09-29, 4차) — §11-2 답: `G1 Z` 에 F 를 붙이지 않는다 (동의, 이유는 정정)

### 12-1. 답
**F 를 붙이지 않는다. 슬라이서는 속도 값을 줄 필요 없다.** Z 이동 속도는 Task0 가 정한다.

### 12-2. 이유 정정 — "Klipper 가 알아서 제한한다"는 절반만 맞다
- Klipper 의 F 는 **직전 값을 물려받는다(modal)**. F 없는 `G1 Z` 는 직전 줄의 F(도포·트래블 속도, 초안 최대 F6000)로 나가고, Z 성분만 `max_z_velocity`(25 mm/s)로 잘린다.
- 즉 리프트 복원이 **최대 25 mm/s** 로 나갈 수 있다. 이 기계 Z 에는 과하다(Task0 리프트 5 mm/s, 옛 Z 이동 2.5~5 mm/s). "제한된다"와 "안전한 속도"는 다르다.

### 12-3. Task0 처리 (슬라이서 무관)
- **실출력 모드**: 순수 Z 이동 줄(X/Y/E 없이 Z 만 있는 `G0`/`G1`)의 F 를 **Task0 Z 속도 설정으로 덮어쓴다**(GUI 조절, 기본 300 mm/min = 5 mm/s, 실험으로 조정). 슬라이서가 F 를 써도 덮어쓰므로 무해.
- **드라이런 모드**: 기존대로 모든 이동 줄 F 고정(부록 A-5). F 없는 줄에는 고정 F 를 붙이므로 충돌 없음(코드 확인).

## 13. Task0 통보 (2026-09-29, 5차) — 하드웨어 배치 확정 → 층 시퀀스 교체 (§10-1·10-2 대체)

### 13-1. 하드웨어 배치 (담당자 측면도 기준)
```
        LED (위에서 아래로 투사)
                                         │Z축 기둥(북쪽)
 [블레이드]           [레진]    [익스트루더]│
 ═════════════ 플레이트 ══════════════════╡ ← 외팔보, 층마다 아래로(+Z)
  남쪽                                북쪽
```
- **익스트루더(X/Y 갠트리) 홈 = 북쪽 (0,0)** — X/Y 엔드스톱이 같은 모서리. 블레이드 홈 = **남쪽**(센서 설치 예정).
- LED 투사 구간은 두 홈 **사이**. 익스트루더·블레이드가 홈에 있으면 빛을 가리지 않는다.
- 블레이드는 남→북(익스트루더 쪽)으로 스윕, 투사 구간 북쪽 끝까지만 간다(그 이상은 홈의 익스트루더와 충돌). 거리는 담당자 실측 후 확정.
- +Z = 플레이트가 노즐·블레이드에서 멀어지는 방향 — **기존 Z 규약 그대로**((N+1)×lh, `G1 Z`에 F 없음).
- 남북 축: 홈이 북쪽 (0,0)이므로 남북 축의 0 = 북쪽. **추정: Y가 남북, +Y = 남쪽**(Y 범위 85 mm가 투사 구간 ~80 mm와 맞음). X/Y 중 어느 쪽인지는 담당자 Motion 탭 확인 후 확정 → 그때 B1 종결.

### 13-2. 새 층 시퀀스 (Task0 삽입 부분 교체)
```
1. G1 Z{(N+1)×lh}                                   ← 슬라이서 (변경 없음)
2. 도포 (T0 → [E-r, T1, E+r] → T1)                   ← 슬라이서 (변경 없음)
3. Z +리프트 → 익스트루더 파킹 (0,0) → Z 복원         ← Task0: 노즐이 돌아가며 도포 레진을 긁지 않게
4. 블레이드 북쪽 스윕 → Z +리프트 → 블레이드 복귀 → Z 복원   ← Task0: 복귀 때 다시 긁지 않게
5. LED ON → exposureSecByLayer[N] → OFF             ← Task0: 둘 다 홈, 가림 없음
```
- §10-1의 모드 A/B는 **폐기**(모드 A 삭제 승인). 시퀀스는 위 하나.
- §10-2 정정: 리프트는 이제 **3·4단계 안에서 매번 복원**된다(리프트 1~2 mm, 기본 1.5). LED 시점과 다음 층 시작 시점의 Z는 항상 층 높이. **그래도 §11-1 불변식(매 층 첫 이동 = 절대 `G1 Z`)은 유지** — 층 이동은 여전히 슬라이서 몫이다.
- **경계 섞임**: 블레이드 복귀 때 Z를 들어 레진에 닿지 않으므로 전단은 **남→북 편도**. "상류 재료 나중" 전략 유효. 상류 = 남쪽(블레이드가 출발하는 쪽).
- **잉여 레진**: 블레이드가 북쪽으로 밀어 **투사 구간 북쪽 끝 바로 밖**에 쌓인다(§8 H1 갱신). 투사 구간 안이 아니므로 슬라이서 영향 없음.

### 13-3. 슬라이서에 요청 2건 (새 구조에서 생긴 것)
1. **층 끝 리트랙트**: 매 층 마지막 도포 뒤 `E-r`, 다음 층 첫 도포 직전 `E+r`. 이유: 익스트루더가 파킹 상태로 블레이드·LED 시간 동안 대기한다. 되감지 않으면 노즐에서 레진이 흘러 플레이트 북쪽(블레이드 경로)에 떨어진다. r 은 재료 프로파일 값(§2-6과 같은 원칙). 층 안 T 전환의 `E-r/T1/E+r` 는 그대로.
2. **층 안 트래블 긁힘**: 3단계를 넣은 이유(노즐이 도포 레진을 가로지르며 긁음)는 **층 안에서도 똑같이** 생긴다 — 섬과 섬 사이 이동, T0 영역 → T1 영역 이동. 도포 직후 레진은 블레이드 평면보다 높게 쌓여 있다(과충전). 제안:
   - **1순위: 도포한 영역을 가로지르지 않는 트래블 경로**(FDM의 "avoid crossing perimeters"와 같은 방식). 이동 거리는 늘지만 Z를 안 움직인다.
   - 불가피한 구간만 Z-hop: `G1 Z{(N+1)×lh + h}` → 트래블 → `G1 Z{(N+1)×lh}`. Task0는 순수 Z 줄 속도를 5 mm/s로 덮어쓰므로(§12) hop 1회 ≈ 2×h/5 초 — 많으면 느려진다.
   - 층 첫 트래블(파킹 (0,0) → 첫 도포점)은 경화된 이전 층 위라 긁힘 없음, 대책 불필요.
   - 이 판단은 슬라이서 몫. 어떤 방식으로 할지 알려 주면 검증기 항목에 넣자.

## 15. Task0 회신 (2026-09-30) — §14 확인 요청 A~D + 14-2 사실관계

### 15-0. 14-2 사실관계 정정 — 복귀 리프트는 Task0가 추가한 게 아니다
- 블레이드 복귀 때 Z 리프트는 **담당자(조우현)가 9/29 직접 지시**한 것이다: "블레이드도 앞으로 가고 난 후 돌아올 때 Z축 이동했다가 다시 원상복구 해야 해." 13-T-2는 그 지시를 옮긴 것.
- 현재 Task0 드라이런 코드는 이 순서로 구현되어 있다(스윕 → Z↑ → 복귀 → Z↓). 리드 답이 "리프트 없음"으로 오면 Task0는 설정 하나(복귀 리프트 on/off)로 바꿀 수 있다. 슬라이서 기본값은 리드 답 기준으로 닫으면 된다.

### 15-A. 출력 시작 시 시린지 상태 — **보장한다: "프라이밍 완료, 리트랙트 안 됨"**
- Task0 실출력 시작 시퀀스(Step 5)에 넣는다: 호밍 → 블레이드 원점 → **사용하는 툴마다 프라이밍**(manifest `materials[].tool` 기준, 단일 재료면 T0만) → 두 툴 모두 언리트랙트 상태로 → `T0` 활성 → run.gcode 시작.
- 따라서 슬라이서 규칙 그대로: **각 툴의 첫 사용 때만 `E+r` 생략**, 이후는 14-3 상태 기계대로. 출력 끝은 모든 툴 리트랙트 상태로 끝나도 되고 Task0 종료 시퀀스는 추가 언리트랙트를 하지 않는다.
- 프라이밍 양·위치는 Task0 소관(슬라이서 무관). 단 **프라이밍으로 나온 레진을 받을 자리(퍼지 컵 등)** 가 하드웨어에 필요 — 담당자 확인 항목으로 넘김(15-E).
- 드라이런(test_2 등)은 파일에 적힌 E를 그대로 실행하므로 이 보장과 무관.

### 15-B. 노즐 끝 ↔ 블레이드 평면 간격 / 도포 직후 레진 높이 — 【담당자 실측 대기】
- 둘 다 하드웨어 수치라 코드로는 알 수 없다. 측정 방법(담당자에게 전달함): ① 간격 = 블레이드를 층 평면에 둔 상태에서 노즐 끝까지 틈새 게이지, ② 레진 높이 = 한 줄 도포 후 측면에서 높이 측정(과충전 1.0/1.2 두 번).
- **답이 오기 전 슬라이서 기본값 제안: "간격 < 레진 높이"(긁힘 있음)로 가정** — 14-4의 1번(북→남 단조 진행)과 2번(칠한 영역 우회)은 기본 켬. 측정 결과 간격이 충분하면 끄면 된다(보수적으로 시작).

### 15-C. 층 안 Z-hop — **Task0 권고: 기본 금지(2번 우회만)**, 최종은 담당자 시험 후
- 근거(코드·설정 기준):
  1. **백래시**: Z는 리드스크류(`rotation_distance: 5`). hop마다 Z 방향이 두 번 바뀌어 백래시가 누적되면 층두께(0.05~0.2 mm) 대비 오차가 크다. Task0 리프트는 층당 2회로 고정·측정 가능하지만, 층 안 hop은 횟수가 모델마다 달라 보정이 어렵다.
  2. **외팔보 진동·레진 출렁임**: Z는 플레이트 전체를 움직인다. `max_z_accel: 1000`이라 짧은 hop도 급가감속 — 미경화 레진이 흔들린다.
  3. **시간**: Task0가 순수 Z 줄을 5 mm/s로 덮어쓰므로 hop 1회 ≈ 2h/5 s.
- 결론: 검증기는 "Z-hop 0건"을 기본 규칙으로. 담당자가 실제 hop 시험(출렁임·층 오차)을 해 본 뒤 허용으로 바뀌면 그때 규칙을 푼다.

### 15-D. 노즐 2개 배치 — 【담당자 확인 대기】 + Task0가 아는 사실
- Task0 설정상 T0/T1은 **서로 다른 스테퍼**(`[extruder]` Motor5, `[extruder1]` Motor6)이지만, X/Y 갠트리는 **하나**다(stepper_x/y 각 1개). 즉 두 노즐은 **같은 캐리지**에 있다 — 별도 캐리지는 아니다. 높이차·리프트 기구 유무는 담당자 확인 필요.
- 같은 높이면 14-5 지적대로 쉬는 노즐이 따라다니며 긁는다. **고정 높이차만으로는 해결 안 된다**: 높은 노즐이 도포할 때는 §2-1 Z 오프셋만큼 플레이트가 가까워져 낮은 노즐이 오히려 층 평면 아래로 들어간다. 해결은 (a) 노즐 리프트 기구(서보 등), (b) 쉬는 노즐의 위치까지 고려한 트래블/도포 경로(노즐 간 XY 오프셋만큼 확장된 영역 회피), (c) 층당 한 재료만(2재료 층 금지) 중 하나. 담당자 답 후 결정.

### 15-E. Task0 → 담당자 확인 목록 (§14 때문에 추가된 것)

## 16. MazicAlign 회신 (2026-09-30) — §15 수용 + 새로 드러난 문제 2건

### 16-1. 수용
- **15-0 정정 수용 — 우리 쪽 오류였다.** 복귀 리프트는 리드가 9/29 직접 지시한 동작이다. **14-2 는 "복귀 리프트 있음"으로 닫는다.** → 전단은 남→북 편도, 경계 섞임 한 방향, 경계 전략 기본값 = "상류(남쪽) 재료 나중" 유효.
- **15-A 수용.** 슬라이서는 각 툴의 첫 사용 때만 `E+r` 을 생략하고, 이후 14-3 상태 기계대로. 출력 끝은 모든 툴 리트랙트 상태.
- **15-B 수용.** 측정 전 기본 가정 = "긁힘 있음". 북→남 단조 진행 + 칠한 영역 우회를 기본 켬.
- **15-C 수용.** 검증기 기본 규칙 = **층 안 Z-hop 0건.** 담당자 시험 후 허용되면 그때 푼다.

### 16-2. 새 문제 ① — Z-hop 금지 + 재료 순서 A→B 고정이면 **치과 핵심 층을 풀 수 없다**
- 잇몸(A)이 치아(B)를 **링처럼 둘러싸는 층**(치아가 소켓에 박힌 높이)이 치과 모델의 핵심 구간이다. A→B 순서면 A 링을 먼저 칠하고, B 섬으로 가려면 **칠한 A 링을 반드시 가로지른다.** 우회 경로가 없다(섬이 링 안에 갇힘). Z-hop 도 금지면 긁힘을 피할 방법이 없다.
- 단일 재료에서도 같은 모양(링 안의 섬)이 나오지만, 그쪽은 **"안쪽 섬 먼저, 둘러싼 링 나중"** 으로 순서를 바꾸면 교차 없이 풀린다.
- **슬라이서 제안**: 재료 순서 규칙을 "기본 A→B, 단 **B 가 A 안에 갇힌 층은 B→A**(안쪽 먼저)"로 바꾼다. 층마다 판정은 슬라이서가 하고 G-code 는 그 순서로 `T` 전환만 한다(Task0 는 무관 — 층 안 T0/T1 순서 가정이 없으면).
- **Task0 확인 요청 E**: 규격서 §7 "서포터(T0) 먼저 → 출력물(T1)" 을 **층마다 바뀔 수 있게** 풀어도 되는가. 파서·워커가 층 안 첫 툴을 T0 로 가정하는 곳이 있으면 알려 달라. 순서를 뒤집으면 출력물 레진(B)이 먼저 깔리고 A 를 나중에 칠하게 되는데, 3-4 의 "출력물 표면 오염 최소화" 근거와 충돌하는지 담당자 판단도 부탁한다.

### 16-3. 새 문제 ② — 쉬는 노즐 긁힘은 **단일 재료 데모에서도** 생긴다
- 15-D: 두 노즐이 같은 캐리지. 그러면 T0 만 쓰는 단일 재료 출력에서도 **T1 노즐이 T0 옆을 같은 높이로 따라다닌다.** T1 이 T0 보다 낮거나 같으면 T0 가 방금 칠한 레진을 긁는다(노즐 간 XY 간격만큼 옆·뒤 영역).
- **데모(단일 재료)용 즉시 대책 제안**: **두 노즐 중 낮은 쪽을 T0(도포 노즐)로** 쓰고, 높은 쪽(쉬는 노즐)이 레진 높이보다 충분히 위에 있게 한다. 하드웨어가 높이차를 줄 수 없으면 데모 동안 T1 노즐(시린지)을 떼어 두는 것도 방법.
- 2재료의 근본 해결(15-D 의 a/b/c)은 데모 후 과제로 둔다. 우리 쪽 선호는 **(a) 노즐 리프트 기구**다 — (b) 경로로 피하면 층 안 순서·우회가 쉬는 노즐 오프셋까지 고려해야 해 16-2 와 겹쳐 거의 풀 수 없는 층이 늘고, (c) 층당 한 재료는 치과 핵심 층(16-2)을 막는다.
- **확인 요청 F (담당자)**: 두 노즐 높이차, 데모에서 어느 노즐을 T0 로 쓸지.

### 16-4. 일정 영향
- 2주차(10/5~) 단일 재료 .zip: 15-A 로 착수 조건 충족. 층 끝 리트랙트·북→남 단조 진행·칠한 영역 우회·Z-hop 0 을 T0-1 범위에 넣는다.
- 16-2(재료 순서 층별 전환)는 2재료 단계(데모 후)에서 구현. 16-3 대책은 데모 전 하드웨어 쪽 결정 필요.

   제안: "**파킹 (0,0) 에서 멀어지는 +Y 방향 단조 진행, 도포 행은 X 방향**". 단일 재료에서는 축이 어느 쪽이든 교차 0 이 보장된다. 남북이 X 로 확정되면 각도만 90° 바꾼다.
2. **§5 리트랙트 상태 기계에 "층 안 짧은 트래블" 예외를 넣어 달라.** 지금 문구("도포하지 않는 동안 모든 툴은 리트랙트")를 엄격히 따르면 줄 채움 행마다 `E-r`/`E+r` 이 붙어 층당 수백 번이 된다.
   제안: "같은 툴의 층 안 트래블 중 **길이 < 1 mm**(retractMinTravel)는 리트랙트 생략 허용. **층 끝과 T 전환 직전은 항상 리트랙트.**" 검증기는 이 예외대로 검사한다.
3. **§4-2 에 "명령 줄 인라인 주석 금지"를 추가해 달라.** 드라이런의 F 치환이 줄 끝에 F 를 덧붙여서, `G1 X1 ; 주석` 이면 F 가 주석 안으로 들어간다(axis_test_page.py `_clean_gcode_line`). 슬라이서는 이미 0 건으로 간다. v0.2 파서에서 주석을 먼저 떼면 더 안전하다.
4. **§3 에 "도포 영역 = 같은 층 PNG 노광 영역" 불변식을 추가해 달라.** 이번 점검에서 우리 G-code 경로가 겹친 솔리드(모델에 박힌 서포트 기둥 등)를 even-odd 합집합으로 처리해 **구멍을 만드는 것**을 발견했다. 마스크는 nonzero 라 그 자리를 채운다. task0 경로는 nonzero 합집합으로 고친다. 검증기: 층 N 도포 표본점의 99% 이상이 `NNNN.png` 의 흰 픽셀 위.
5. **§11 estimate 에 parkSec·bladeSec 추가 — 찬성.** 필드: `depositSec, travelSec, toolChangeSec, parkSec, bladeSec, layerOverheadSec, exposureSec, totalSec`. totalSec 는 합계.
6. **§1 투사 영역은 단일 피치 p 로 정의하자: 1920·p × 1080·p.** DMD 픽셀은 정사각이다. 잠정 "140 × 80" 에 맞춰 축별로 늘리면(72.9 / 74.1 µm) Y 가 약 1.6% 늘어나 치과 정밀도에 직접 걸린다. p = 73 µm 이면 140.2 × 78.8 mm. 정렬 잡에서는 **p 와 시작점 두 값만** 재면 된다. 출력 가능 영역은 노즐 Y 85 제한 때문에 140 × 75 그대로다.

### 22-3. 추가 제안 (d) — 도포폭보다 얇은 형상이 (a)(b)(c) 를 모두 빠져나간다
