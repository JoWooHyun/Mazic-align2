# S-0 진단 결과 — "아일랜드에 서포트 달기 안 됨" 원인 확정 (2026-07-15)

- 방법: integrate/v2-mainline 최신(aea55be)의 실제 검출·생성 코드를 headless(Babylon NullEngine)로
  직접 실행해 실측. 진단 스크립트 보존: 워크트리 `scratchpad/s0-diag/frontend/diag-island-support.ts`
- **판정: (a) 명백한 버그(설계 결함).** 파이프라인 연결(PR #20)은 살아 있으나
  생성 알고리즘이 "아일랜드"라는 입력에 구조적으로 부적합.

## 원인 (비개발자용 요약)

서포트 자동 생성이 **아일랜드 위에 점을 찍는 방식이 아니라**, 모델 전체에 **4mm 간격 바둑판**을
깔고 그 교차점이 "우연히" 아일랜드 위에 떨어질 때만 서포트를 만든다.
치과 모델의 아일랜드(커스프 등)는 몇 mm² 이하로 작아서 4mm 바둑판에 사실상 안 걸림 → **생성 0개**.
게다가 당시 빌드에는 0개여도 아무 알림이 없어서 "눌러도 아무 일 없음"으로 보였다.

## 실측 증거

| 시나리오 | 결과 |
|---|---|
| 반지름 0.5mm 아일랜드(치과 커스프 규모), 기본 4mm 간격 | 생성 **0개** |
| 간격을 최소 1.5mm로 줄여도 | 64개 생성되나 **아일랜드 위 0개** (전부 본체 바닥) |
| 격자점이 정확히 아일랜드 중심에 올 때만 | 1개 |
| 모델을 플레이트에 딱 붙인 경우(바닥면 정렬) | **전량 0개** — 높이 0.5mm 이하 후보를 버리는 필터에 전멸 |

## 함께 발견된 부수 결함

1. **바닥 전체가 아일랜드로 검출됨**: 리프트 5mm 기본값으로 모델이 공중에 뜬 상태에서
   첫 레이어가 무조건 아일랜드 판정 → 마젠타가 바닥 전체를 덮음.
   지현규의 "아일랜드 찾기는 되는 것 같은데 확실하지 않음"과 정합.
2. **y≤0.5mm 하드컷**: 플레이트에 붙인 모델은 서포트 후보가 100% 폐기됨.
3. **0건 무통지(당시)**: 0건 안내 문구는 7-15 PR #33에서야 추가됨. 지현규 테스트 시점엔 없었음.
4. 0건 메시지가 "마진 가드 등으로 배제"라고 오귀인 — 실제 원인과 다름.

## 기각된 후보 (원인 아님)

- 마진 가드 / B10(bodyR): 배제 반경 0.9mm에 불과, 전량 배제 불가
- 상태 연결 끊김 / 렌더 누락 / 에러 삼킴 / 7-09 이후 PR 회귀: 전부 아님 (코드·이력 확인)

## 수정 방향 (서포트 재설계 S-3 인터페이스 논의와 합류)

1. 격자 필터링 → **아일랜드 face 집합에서 직접 샘플링** (face centroid 기반 — v1 방식이 원래 이랬음)
2. 첫 레이어 무조건-아일랜드 → plateGap 또는 "리프트 높이 이하 제외" 처리
3. y≤0.5 하드컷 → 리프트 설정과 연동
4. 0건 메시지 오귀인 문구 수정

## 지현규 확인 질문 (판정 보강용, 필수 아님)

1. 버튼 클릭 시 아무 반응이 없었나, 아니면 서포트가 생기긴 했는데 엉뚱한 곳(바닥)이었나?
2. 테스트 때 모델을 플레이트에 붙였나? (바닥면 정렬 사용 여부)
3. 마젠타 표시가 커스프에만 떴나, 바닥 전체를 덮었나?
