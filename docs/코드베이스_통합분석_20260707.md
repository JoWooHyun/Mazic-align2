1. 세 코드베이스는 **같은 커밋(`b5c3339`, README 개정)에서 갈라진 3형제**다. git 3-way 머지가 기술적으로 가능하다.

## 5. 통합 선택지

### 옵션 1 (권장 후보): B(유승제 브랜치)를 새 메인라인으로

- 근거: 가장 많은 인프라(프로젝트 관리, undo, 프로파일, ctb 출력)가 이미 있고, v1도 포함하므로 A·C의 작업을 "이식"으로 수용 가능. 문서-코드 정합성 검증 완료.
- 해야 할 일: A의 미커밋 Step1~2 중 B에 없는 것(FDM G-code 강화, 툴바/단축키 일부) 선별 이식, C의 마진/아일랜드를 v2 모듈로 이식(면적 큼), 데이터 계층 IndexedDB로 확정(백엔드 역할 재정의).
- 리스크: C의 코드가 v1 STLViewer에 깊이 결합(4,137줄 단일 파일, 시그널 패턴)돼 있어 v2 BabylonScene으로 옮기는 비용이 큼. C 이식은 "마진/아일랜드 알고리즘(순수 로직)"과 "뷰어 결합부"를 분리해서 알고리즘부터 옮기는 전략 권장.

### 옵션 2: A(이 저장소)를 메인 유지, B의 v2 폴더만 수입

- 근거: 사장님 개발계획서 기준 유지. C의 코드가 v1 기반이라 C 통합은 상대적으로 쉬움.
- 리스크: B의 v1 개조(+1,700줄)와 신규 인프라(IndexedDB, undo, ctb)가 이중화되거나 폐기 — B의 129커밋 가치 절반 손실.

### 옵션 3: 당분간 병행 — 갈라짐이 더 커질 뿐. **비권장.**

### 서포트 통합 (어느 옵션이든)
