## 이미 대등하거나 우리가 나은 것 (도입 불필요)

| 기능 | 비교 |
|---|---|
| **마진(변연) 검출** | **프루사에 없음 — 우리만 있음.** dental 시장 차별점 (지현규 잠금 알고리즘) |
| **dental 원클릭 워크플로우** | 브러쉬→마진→아일랜드→위험영역 자동 서포트 — 프루사에 없는 조합 |
| 아일랜드(미지지) 검출 | 양쪽 있음 — 우리 것이 마진·서포트와 연계돼 실용적 (단 대형 모델 성능 보류 건) |
| 페인트-온 (칠해서 지정) | 양쪽 있음 — 우리 브러쉬가 dental 용도로 대등 |
| 서포트 (기둥/브릿지 편집) | 프루사가 범용으로 성숙하나, 우리는 dental 특화(disc·마진 가드) + 실시간 편집 UX가 강점 |
| **CTB 출력** | 프루사는 자사 SL1 계열만 — **CTB는 우리만** (시중 LCD 프린터 호환) |
| 시간/재료 추정, 프로파일 | 양쪽 있음 (프루사가 더 정교하나 충분) |
| 웹 기반 | 설치 불요·즉시 배포·협업 — 프루사가 못 하는 것 |

## 추천 시나리오

**패키지 A (품질 스프린트, ~1주)**: ⭐1 안티앨리어싱+코끼리발 — 작고 즉효, 실기 검증의 날 전에 넣으면 출력 비교 가능
**패키지 B (재료비 스프린트, ~1개월)**: ⭐2 홀로잉+드레인홀 — dental 실사용 가치 최대, CSG 자산 재활용
**패키지 C (편의 스프린트, ~2주)**: ⭐3 자동 배치 + 4 오리엔테이션 재활성

권장 순서: **A → (실기 검증) → B → C.** A는 하이브리드 회의 결과와 무관하게 유효 (마스크 품질은 어느 트랙이든 필요).

## 결정 방법

이 표에서 **패키지(A/B/C) 또는 개별 번호**로 골라주면 → 해당 기능의 상세 계획(Step·수용 기준)을 만들어 dev-cycle로 진행. 프루사 코드는 열어보지 않고 공개 문서·논문 수준의 개념만 참조해 재구현한다 (AGPL 안전).
