# 2노즐 하이브리드 — 기획 회의용 기술 브리핑 + 선택지

- 작성: 2026-07-09 (AI, 3인 회의 사전 자료)
- 목적: "최종 목표"였던 2노즐 레진 경로 도포를 **다음 개발계획서의 주제**로 올리기 위한 현황·격차·결정 사항 정리
- 읽는 데 10분. 회의에서 결정할 것은 **4개 안건**뿐입니다 (3장).

## 1. 우리가 이미 가진 것 (3일 통합의 결과물)

하이브리드의 재료가 사실상 전부 v2에 모여 있습니다:

| 자산 | 상태 | 하이브리드에서의 역할 |
|---|---|---|
| **FDM G-code 파이프라인** (조우현) | ✅ 워커화까지 완료 | 노즐 경로 생성의 본체 — 벽/인필/리트랙션/팬 완비. 단 **단일 노즐 기준** |
| **마진 검출** (지현규, 잠금) | ✅ v2 모듈화 | **영역 경계의 근거** — 마진 폐곡선(points/edgeKeys)이 "인레이 vs 지지" 를 가르는 선 |
| **아일랜드/오버행 검출 + 서포트** (지현규+유승제) | ✅ 파이프라인 연결 | 지지 소재 노즐이 가야 할 곳의 판단 |
| **manifold CSG** (유승제) | ✅ 보유 (서포트 컷용) | mesh를 영역별로 자르는 도구 (선택지 2-A의 기반) |
| **폴리곤 클리핑** (js-clipper) | ✅ G-code에서 사용 중 | 2D에서 영역을 나누는 도구 (선택지 2-B의 기반) |
| DLP 마스크/CTB, 슬라이스 프리뷰, 프로파일, 워커 인프라 | ✅ | 공정 병행/검증 수단 |

## 2. 없는 것 (기술 격차 — 개발계획서에 들어갈 것들)

1. **레이어 다중 영역 데이터 모델**: 지금은 레이어당 "폴리곤 한 묶음 or 마스크 한 장". "이 폴리곤들은 노즐A(인레이), 저건 노즐B(지지)"를 담는 구조가 없음 — 모든 것의 선행 작업
2. **영역 분리 알고리즘**: 마진 폐곡선(3D 라인)을 "레이어별 안/밖 영역"으로 바꾸는 방법 (선택지 2)
3. **다중 노즐 G-code**: 툴체인지(T0/T1), 노즐 간 오프셋 보정, 전환 시 프라임/와이프, 재료별 온도·압출 파라미터
4. **2색 경로 프리뷰**: 만든 경로가 맞는지 눈으로 확인할 수단 (v1의 경로 시뮬레이션 프리뷰를 2색으로 확장)
5. **하드웨어 확정** (기술 아닌 제품 결정): 실제 장비 스펙 — 아래 안건 3

## 3. 회의에서 결정할 안건 4개

### 안건 1. 제품 형태 — "하이브리드"의 정확한 의미
- **A안**: DLP 경화는 유지 + 노즐은 **보조** (서포트/2차 재료만 노즐 도포)
- **B안**: 노즐이 **주** — 레진을 FDM처럼 경로 도포 (DLP 대체)
- **C안 (추천)**: 단계적 — **1단계: 단일 노즐로 특정 영역만 경로 출력하는 데모**를 최소 목표로 삼고, 결과를 보고 A/B를 정함
- 추천 근거: 하드웨어가 확정되지 않은 상태에서 A/B를 정하면 소프트웨어가 추측 위에 서게 됨. C안이면 지금 자산으로 2~3주 내 데모 가능.

### 안건 2. 영역 분리 방식 (기술 핵심)
- **A안 (3D 분리)**: 마진 폐곡선으로 mesh를 CSG 절단 → 인레이 sub-mesh / 지지 sub-mesh → 각각 기존 파이프라인 통과. 유승제 manifold 자산 활용. 장점: 개념 깔끔, 영역별 독립 처리. 난점: 폐곡선→절단면(surface) 생성이 비자명
- **B안 (2D 분리, 추천)**: 슬라이스는 한 번 → 레이어마다 마진 라인의 해당 높이 단면(폴리곤)으로 클리핑해 안/밖 폴리곤 분리. js-clipper 자산 그대로, G-code 파이프라인 입력 형태(Point[][])와 즉시 호환. 난점: 마진 라인을 레이어별 닫힌 2D 폴리곤으로 만드는 전처리
- 추천 근거: B안이 기존 코드와의 접점이 압도적으로 많고, 실패해도 A안으로 갈아탈 때 재사용됨. **지현규(마진 데이터 구조)·유승제(CSG) 두 분의 기술 의견이 가장 필요한 안건.**

### 안건 3. 대상 하드웨어 확정 (사내 결정)
소프트웨어가 답할 수 없는 것들 — 회의 전에 하드웨어 쪽에서 준비되면 좋을 답:
- 시험 장비: 어떤 프린터/프레임에 노즐을 얹나? 펌웨어는? (Marlin/Klipper — G-code 방언이 갈림)
- 노즐 전환 방식: 툴체인저? 듀얼 고정 헤드(오프셋)? → G-code 명령이 달라짐
- 레진 도포 방식: 압출? 디스펜서(공압)? → 압출량(E) 모델이 달라짐
- 경화: 도포 후 UV 즉시 조사? 레이어 단위? → 공정 순서(G-code 삽입 명령)가 달라짐

### 안건 4. 1차 마일스톤 정의 (추천안 포함)
추천: **"M1 데모: STL을 로드하고 마진을 찾으면, 마진 안쪽 영역만의 단일 노즐 G-code가 나온다 + 2색 프리뷰로 확인"**
- 하드웨어 없이도 완성/검증 가능 (프리뷰 + NC Viewer)
- 필요한 개발: 격차 1(데이터 모델) + 2(영역 분리 B안) + 4(프리뷰) — 격차 3(툴체인지)은 하드웨어 확정 후
- 이게 되면 실기가 준비되는 순간 "노즐B 추가"는 증분 작업

## 4. 회의 후 흐름 (참고)

안건 4가 결정되면 → AI가 개발계획서 초안(Step 단위, 수용 기준 포함) 작성 → 3인 검토 → 지금과 같은 dev-cycle로 진행. 마진 잠금·산출물 보존 등 기존 규약은 그대로 적용.

## 5. 한 장 요약 (회의 시작할 때 읽을 것)

> 재료는 다 모였다. 결정할 것은 ① 하이브리드의 의미(단계적 접근 추천) ② 영역을 3D로 자를지 2D로 자를지(2D 추천, 기술진 의견 필수) ③ 하드웨어 스펙(사내) ④ 첫 데모의 범위(마진 안쪽 단일 노즐 G-code + 2색 프리뷰 추천). 이 4개가 정해지면 개발계획서 초안은 AI가 바로 만든다.
