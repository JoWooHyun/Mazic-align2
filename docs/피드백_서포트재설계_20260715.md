# 팀원 사후 확인 결과 — 서포트 재설계 필요 판정 (2026-07-15)

- 수신: 조우현(리드)이 팀원 확인 결과를 구두/메신저로 수령, AI가 기록
- 성격: **다음 개발 방향을 정하는 피드백** — "통합 코드 완료 후 신규 계획 없음" 상태를 뒤집음

## 1. 유승제 — PR #19 (dental disc 서포트) 확인 결과

> **대대적인 변화가 필요. 서포트 알고리즘이 근본적으로 부족 — 아예 처음부터 해야 할 수준.**
> 조우현에게 도움 요청.

- 사후 확인 3건(A안 동의 / disc 재생성 허용 / gizmo 이동 비활성) 차원을 넘어,
  **서포트 생성 알고리즘 자체의 재설계** 판정.
- 리드 의견: PrusaSlicer의 레진(SLA) 서포트 알고리즘을 참고해야 할 듯.
  모양, 꺾이는 각도, (모델에) 들어가는 깊이 등 전면 재작업 필요.
  꼭 프루사가 아니더라도 여러 오픈소스 참고.

## 2. 지현규 — PR #14 (마진 찾기) + 아일랜드 확인 결과

> 마진 찾기 기능은 **된다. 그러나 작은 파일만** 잘 된다.
> 치아 전체 파일 같은 **큰 파일은 찾기 힘들어지고 멈춘다**.
> 아일랜드 찾기는 되는 것 같은데 확실하지 않음.
> **아일랜드에 서포트 달기는 안 된다.**

- 마진 대형 멈춤: 기존 파악 사항과 일치 — 마진 찾기 24초 메인스레드 블로킹(워커화 결정 대기)
- 아일랜드 대형: 기존 보류 결정(2026-07-14, 셀 수 폭발 + 메인스레드)과 일치
- **아일랜드→서포트 달기 실패는 신규 보고**: Step 2-4(PR #20)의 검출→생성 파이프라인이
  실사용에서 동작하지 않음. **원인 미확인 — 버그인지 사용법 문제인지 진단 필요.**

## 3. 리드(조우현) 종합 판단

> 공통적으로 **서포트 쪽을 제대로 구현하지 않고 지나와서** 생긴 문제로 보임.
> 서포트를 제대로 보강한 뒤 다음 스텝으로 넘어가야 함. **공부가 필요.**

## 4. 파생되는 것

### 즉시 진단 (버그 가능성)
- [ ] 아일랜드→서포트 달기 "안 됨"의 원인 확인 (PR #20 파이프라인 진단)

### 성능 (기존 결정 대기 건이 이 프로그램에 편입됨)
- [ ] 마진 찾기 워커화 — 대형 파일 멈춤의 직접 해법. 로직 무변경(잠금 준수) + 지현규 컨펌
- [ ] 아일랜드 검출 워커화/cellSize 분리 — 보류 해제 여부 재검토

### 연구/공부 (서포트 재설계의 선행)
- [ ] PrusaSlicer SLA 서포트 알고리즘 분석 (JoWooHyun/PrusaSlicer 포크 이미 보유)
- [ ] 기타 오픈소스 조사 (UVtools 등) + 학술 자료
- [ ] **라이선스 확인 필수**: PrusaSlicer는 AGPL — 코드 이식 시 제품 소스 공개 의무 발생 가능.
  알고리즘 개념 참고와 코드 복사는 법적으로 다름. 조사 단계에서 라이선스 표 작성할 것.
- 참고: v4 계획서(2026-03, 프루사 포크 단독 결정)가 이 방향과 수렴 —
  당시 "참고자료로만 유지" 판정했으나 서포트 재설계 논의에서 재평가 가치 있음

### 재설계 설계 결정(연구 후)
- 서포트 형상(기둥/트리/브랜칭), 접점 형상과 침투 깊이, 꺾임 각도,
  오버행 각도 기준, 밀도/간격, 검출(지현규)→생성(유승제) 인터페이스 재정의

## 5. 역할 연결

- 유승제 = 구조물 생성/편집 담당 → 재설계의 주 수혜자이자 협업 대상 (본인이 도움 요청)
- 지현규 = 배치 판단 담당 → 검출 성능(워커화) + 검출→생성 입력 규격 협의
- 아키텍처결정 ADR-3(검출→생성 파이프라인)은 유지 — 파이프라인 위의 "생성" 부분을 재설계
