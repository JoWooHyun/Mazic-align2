## 0. 이 설계의 전제 (반드시 먼저 읽고 시작할 것)

이 세 가지는 협상 대상이 아니라 **출발선**이다. 설계 전체가 여기서 갈라진다.

### 전제 ① — FDM 서포트 방식은 절대 쓰지 않는다

FDM(필라멘트 녹여 쌓는 프린터)의 서포트는 **벽과 인필(속채움)을 한 층 한 층 쌓아 올려, 출력물 아랫면을 넓은 "면"으로 받치는 구조물**이다. 나중에 손이나 도구로 뜯어낸다. 우리가 만드는 것은 레진(SLA/DLP) 프린터용이고, 원리가 완전히 다르다.

레진은 액체가 빛을 받아 굳는다. 출력물을 받치는 힘은 크지 않아도 되고, 대신 **뜯어낸 자국이 최소여야** 한다(치과 모델은 표면 정밀도가 생명). 그래서 레진 서포트는 **가느다란 기둥이 출력물에 "점"으로 살짝 닿는** 형태다. 닿는 면적이 작을수록 자국이 작고 떼기 쉽다.

| | FDM 서포트 | 레진 서포트(이 설계) |
|---|---|---|
| 접촉 방식 | 넓은 **면**으로 받침 | 뾰족한 **점**으로 받침 |
| 구조 | 벽+인필을 층층이 쌓음 | 가는 기둥 하나 + 화살촉 접점 |
| 목적 | 무너지지 않게 넓게 지지 | 자국 최소 + 떼기 쉬움 |

**따라서 이 설계에는 "벽", "인필", "면 접촉", "층별 서포트 슬라이스 채움" 같은 FDM 개념이 한 줄도 들어가지 않는다.** 서포트는 3D 기둥 구조물이고, 나중에 모델과 합쳐 통째로 슬라이스한다.

### 전제 ② — 일반 bottom-up 레진 방식을 기준으로 설계한다

우리 실제 하드웨어는 **top-down(위에서 아래로 굳히는)** 방식이다. 하지만 top-down 서포트에 대한 공개 자료가 거의 없다. 반면 bottom-up(아래에서 위로 굳히는, 일반적인 데스크톱 레진 프린터 방식)은 검증된 자료와 오픈소스가 있다.

**그래서 이 설계는 검증된 bottom-up 개념 위에서 짠다.** 서포트의 모양·각도·점 찍는 규칙 같은 뼈대는 두 방식이 사실상 같다. 다른 것은 **힘의 방향과 세기**(bottom-up은 필름에서 떼는 박리력이 크게 작용, top-down은 다름)뿐이다.

> top-down 특수성(밀도를 얼마나 촘촘히, 팁을 얼마나 튼튼히)은 **리드가 실기로 확인한 뒤 별도로 지시할 몫이며, 이 문서 범위 밖이다.** 이 문서의 수치는 전부 "우리 프린터·레진으로 실측 재검증 필요"인 출발점이다.

### 전제 ③ — 학습 정본은 PrusaSlicer SLA, 단 클린룸

레진 서포트를 자동 생성하는 참고 가능한 오픈소스는 사실상 **PrusaSlicer SLA 하나**뿐이다. 이 설계의 개념·수치는 대부분 거기서 배운 것을 우리 언어로 재구성했다.

- **PrusaSlicer는 AGPL 라이선스다.** 개념과 수치(아이디어)는 저작권 보호 대상이 아니라 배워도 되지만, **코드는 한 줄도 복사·번역(C++→TypeScript 이식 포함)하면 안 된다.** 그러면 우리 상용 제품 전체 소스를 공개해야 하는 의무가 생긴다.
- **구현 원칙 = 클린룸.** 프루사 코드를 열어 보면서 베끼지 말고, **이 문서(와 연구 보고서)를 스펙으로 삼아 처음부터 새로 만든다.**
- NanoSupport(nano3Dtech) 등 상용 도구는 소스·문서가 비공개라 알고리즘을 배울 수 없다. **"small/medium/large 3분류 + 홀로우(속 빈) 서포트" 같은 UI 아이디어 정도만** 참고 가능하다.

## 1. 서포트가 왜 필요한가 — 레진 서포트의 기본 개념

레진 프린터는 출력물을 **한 층씩 얇게 굳혀 쌓는다.** 이때 두 가지 문제가 생긴다. 서포트는 이 둘을 붙잡아 주는 임시 기둥이다.

### 아일랜드(island) = 공중에 뜬 조각

어떤 층에서 **처음 등장하는데 바로 아래층에 연결된 부분이 하나도 없는** 조각. 아래에 아무것도 없으니 붕 떠 있다. 안 받치면 굳는 순간 레진 통 안에 **떨어져 나가 떠내려간다** → 출력 실패.

예: 치아 모델의 뾰족한 산(커스프)이나, 브릿지 아래 매달린 부분처럼, 아래보다 위가 먼저 나타나는 형태.

### 오버행(overhang) = 처지는 가장자리

**아래층보다 바깥으로 튀어나온 가장자리.** 완전히 떠 있지는 않지만, 받쳐 주는 것 없이 옆으로 뻗어 나가면 **아래로 휘거나 처진다.** 특히 수평에 가까울수록(눕는 각도가 클수록) 심하다.

### 정리

| 무엇 | 상태 | 안 받치면 |
|---|---|---|
| 아일랜드 | 아래에 연결 0 (완전히 뜸) | 떨어져 떠내려감 → 실패 |
| 오버행 | 아래보다 튀어나옴 (부분적으로 뜸) | 휘거나 처짐 → 정밀도 저하 |

서포트의 임무는 **이 두 곳을 골라내서(검출), 각각에 알맞은 기둥을 세워(생성), 바닥판까지 연결해 안정시키는 것**이다.

## 2. 전체 그림 — 파이프라인

서포트 만들기는 **네 덩어리**로 흐른다. 각 덩어리가 "무엇을 받아 무엇을 내놓는지"가 이 설계의 핵심이다. (검출과 생성을 얇은 인터페이스로 나누는 것이 지현규/유승제 분담과 정확히 맞는다 — ADR-3 파이프라인 유지, 내용물만 교체.)

```
슬라이스된 층들
      │
      ▼
 ① 어디를 받칠지 점 찍기   ← 지현규 영역 (검출·배치 판단)
      │  내놓는 것: "서포트 점 목록" {위치, 팁 반경, 타입}
      ▼
 ② 그 점에 실제 기둥 세우기 ← 유승제 영역 (구조물 생성)  ★이 문서의 핵심
      │  내놓는 것: 서포트 3D 구조물(접점+기둥+다리)
      ▼
 ③ 바닥판(패드/래프트) 깔기
      │  내놓는 것: 기둥 발밑을 잇는 판
      ▼
 ④ 출력에 합성
         서포트도 모델과 함께 층별로 슬라이스해 마스크/CTB에 합쳐 넣음
```

| 단계 | 입력 | 출력 | 담당 |
|---|---|---|---|
| ① 점 찍기 | 슬라이스된 층 폴리곤들 | 서포트 점 목록 | 지현규 |
| ② 기둥 세우기 | 서포트 점 목록 + 모델 형상 | 서포트 3D 구조물 | 유승제 ★ |
| ③ 바닥판 | 기둥 발 위치들 | 바닥판 구조물 | 유승제 |
| ④ 합성 | 모델+서포트+바닥판 | 층별 마스크/CTB | 슬라이서 코어(조우현) |

**둘 사이의 계약(인터페이스)은 오직 "서포트 점 목록" 하나다.** 지현규는 "여기, 여기, 여기를 받쳐라(각 점의 위치·필요한 팁 굵기·타입)"만 넘긴다. 유승제는 그 점을 받아 "어떻게 세울지"만 책임진다. 서로의 내부는 몰라도 된다.

## 3. ① 점 찍기 — 어디를 받칠까 (지현규 검출과의 인터페이스)

> 이 장은 **지현규 영역**이다. 유승제 입장에서는 "내가 무엇을 입력으로 받는가"를 아는 것이 목적이므로, 개념 위주로만 정리한다. 상세 알고리즘은 지현규 개발방향 문서와 별도 협의로 확정한다.

### 3-1. 2D 층 그래프로 아일랜드/오버행/반도 구분

3D 메시를 직접 분석하지 않는다. **이미 슬라이스된 2D 층 폴리곤들을 아래에서 위로 훑는다.** 우리 `SliceEngine`이 이미 층 폴리곤을 만들고 있으므로 자연스럽게 접목된다.

- 각 층의 폴리곤이 **바로 아래층 폴리곤과 겹치는지** 본다.
- 아래층과 하나도 안 겹치면 → **아일랜드**.
- 겹치지만 바깥으로 새로 튀어나온 부분이 있으면 → **오버행**.
- 한 층에서 2mm 이상 크게 튀어나온 넓은 오버행은 가장자리뿐 아니라 **안쪽도 받쳐야** 한다 → **반도(peninsula)**.

### 3-1b. 오버행 검출 기준각 (CHITUBOX 대조로 추가, 2026-07-20)

오버행을 "받칠지 말지" 가르는 **기준각**이 있다. CHITUBOX의 "Angle(각도)" 파라미터가 이것으로, 툴팁 정의는 *"모델 표면이 플레이트(바닥)와 이루는 최대 기울기 — 이보다 더 누우면 서포트를 붙인다"*이다.

- **모델 표면이 수직(90°)에 가까우면** 스스로 서니 안 받쳐도 된다.
- **수평(0°)에 가까울수록** 처지므로 받쳐야 한다.
- 이 **기준각보다 더 누운(수평에 가까운) 면**을 오버행으로 판정해 점을 찍는다. CHITUBOX 기본값은 30°.

> **★ 주의 — 이 각도는 4-3의 "45° 단일 규칙"과 전혀 다른 각도다. 혼동 금지.**
> - **여기(검출각)** = "어디를 받칠지 **고르는**" 각도 (점 찍기, 3장).
> - **4-3(구조각 45°)** = 서포트 **구조물이 기울 수 있는 한계** 각도 (기둥·다리 만들기, 4장).
> - 즉 CHITUBOX도 이 둘을 **별개 파라미터로 나눠 둔다**(Auto 탭의 Angle=검출각, Middle 탭의 Angle=구조 기울기각). 우리 설계는 구조각을 45° 하나로 통일하되, **검출각은 별도 파라미터로 둔다**(출발점 30°, 실측 재조정 대상).

### 3-2. 밀도 = "z높이에 따라 지지 반경이 커지는 경험 곡선" (힘 계산 아님)

**중요: 물리 시뮬레이션(힘·모멘트 계산)을 하지 않는다.** 프루사도 예전엔 힘 모델을 썼지만 버리고 이 단순한 방식으로 갈아탔다 — 단순한 쪽이 이겼다.

개념은 이렇다. 서포트 점 하나가 세워지면 그 점은 주변 일정 반경까지 "책임진다(지지한다)". 이 **지지 반경은 받쳐야 할 지점이 바닥에서 높이 떠 있을수록 커진다.** 새로 받쳐야 할 지점이 기존 어떤 점의 지지 반경 안에도 안 들어오면, 거기 새 점을 찍는다. 그게 전부다.

**지지 반경 경험 곡선 (프루사값, 출발점 — 우리 레진으로 실측 재검증 필요):**

| z 높이(mm) | 지지 반경(mm) | 뜻 |
|---|---|---|
| 0 | 3.2 | 바닥 근처는 촘촘히 |
| 3.9 | 4.0 | |
| 15 | 5.0 | 높아질수록 |
| 40 | 6.0 | 반경 넓어짐 = 성기게 |

반경이 클수록 점이 성기게 찍히고(적게), 작을수록 촘촘하게(많이) 찍힌다. **왜?** 낮은 곳은 층이 얇게 굳는 초기라 잘 떨어져 촘촘히 잡아야 하고, 높은 곳은 이미 어느 정도 형태가 잡혀 성기게 잡아도 되기 때문. (top-down에서는 이 곡선이 다를 수 있어 실측 재조정 필요.)

### 3-3. 아일랜드 크기별 3분기

아일랜드는 크기·모양에 따라 점 찍는 방식이 다르다.

| 아일랜드 모양 | 점 찍기 | 왜 |
|---|---|---|
| **작음** | 중심에 **1점** | 작으니 하나로 충분 |
| **가늘고 긴 것** | 양 끝에 **2점** | 한가운데 하나만 두면 시소처럼 기울어짐 |
| **큰 것** | 가는 부분은 **뼈대(중심선)를 따라**, 굵은 부분은 **둘레 + 내부 격자**로 여러 점 | 넓으니 전체가 처지지 않게 골고루 |

- 어디가 "가늘고" 어디가 "굵은"지 판정하는 도구는 아일랜드 모양의 **뼈대(스켈레톤)의 최장 경로**다. 1차 버전은 뼈대 계산 대신 **최대 내접원·바운딩박스 같은 근사**로 시작해도 된다.
- 크기 경계값(예: "이 정도까지는 1점으로 버틴다")은 **"실제 팁 굵기로 인쇄해 버티는 한계를 실측한 뒤 나온 회귀값"**이다. 이 순서 — 먼저 실험, 그다음 수식 — 가 중요하다. 우리도 우리 레진으로 실측해서 경계값을 정해야 한다(→ 9장 결정 사항).

### 3-4. 인터페이스 = "서포트 점 목록" (지현규 → 유승제 계약)

지현규가 유승제에게 넘기는 것은 오직 이 목록이다.

**서포트 점 하나 = { 위치(x, y, z), 필요한 팁 반경, 타입(island / slope / manual) }**

- **위치**: 받쳐야 할 지점의 3D 좌표.
- **팁 반경**: 이 점이 얼마나 굵은 접점을 요구하는지(작은 아일랜드는 가는 팁, 넓은 곳은 굵게).
- **타입**: 아일랜드에서 온 점인지, 오버행(slope)에서 온 점인지, 사용자가 손으로 찍은 점(manual)인지. 유승제가 세부 규칙을 다르게 적용할 수 있게.

**이 계약이 있으면 두 사람이 독립적으로 일할 수 있다.** 유승제는 "이 점들이 어떻게 나왔는지" 몰라도, 목록만 받으면 기둥을 세울 수 있다.

## 4. ② 기둥 세우기 — 어떻게 받칠까 (유승제 영역) ★이 문서의 핵심

점 목록을 받아, 각 점에 **실제 3D 구조물**을 세운다. 아래가 이 설계에서 유승제가 만들어야 할 실체다.

### 4-1. 접점(핀헤드) — 출력물에 닿는 뾰족한 끝

출력물에 살짝 닿는 부분. 모양은 **화살촉**이다.

```
   (모델 표면)
      ╲  ← 0.2mm 파고듦(침투)
   ● ─ 앞구슬 (⌀0.4mm)  ← 실제로 모델에 닿는 뾰족한 끝
    ╲
     ▼ ─ 원뿔 (점점 굵어짐)
    ╱
   ● ─ 뒷구슬 (⌀1.0mm)  ← 기둥과 이어지는 굵은 쪽
    │
    │ ← 기둥으로 이어짐
```

- **앞구슬(팁)**: 지름 **0.4mm**. 실제로 모델에 닿는 뾰족한 끝. 가늘수록 자국이 작고 떼기 쉽지만 약하다.
- **침투 깊이**: 앞구슬이 모델 표면을 **0.2mm 파고든다.** 살짝 박혀야 안 미끄러지고 확실히 붙는다. 파고드는 만큼 자국이 남으므로 최소로.
- **원뿔 + 뒷구슬**: 앞구슬(0.4mm)에서 뒷구슬(**1.0mm**)로 매끄럽게 굵어지며 기둥에 연결. 접점 길이(구슬 중심 간)는 약 **1.0mm**.
- **방향**: 접점은 모델 표면이 향한 방향(법선)을 따라 붙되, **수평 45°보다 눕지 못하게** 제한한다(아래 4-3).

**수치는 프루사값(출발점) — 우리 레진·프린터로 실측 재검증 필요.** 치과 모델은 더 가는 팁(예: 0.2mm대)을 쓰기도 한다(5장).

### 4-2. 기둥 — 접점에서 바닥으로 내리는 몸통

- 접점(뒷구슬)에서 **아래로 수직 하강**해 바닥판까지 내려가는 가는 막대.
- 굵기: 지름 **1.0mm**(출발점). 치과 실무에서는 1.5~2mm를 쓰기도 한다.
- 기본은 수직. 아래에 모델이나 다른 장애물이 있으면 4-4의 폴백으로 피한다.

### 4-3. ★ 꺾임 각도 = 45° 단일 규칙 (조우현이 특히 궁금해한 부분)

> 여기서 말하는 각도는 **구조물이 기울 수 있는 한계각**이다. "어디를 받칠지 고르는" 오버행 검출각(3-1b)과는 다른 각도이니 혼동하지 말 것.

**이 시스템의 모든 꺾임·경사·기울기(구조물 쪽)는 하나의 각도 파라미터로 통일한다. 기본값 45°, 사용자 조절 가능(0~90°).** 하나로 묶되 값은 열어 둔다 — 이게 단순함과 유연함을 함께 얻는 방식이다. (리드 결정 2026-07-20: 잠그지 말고 사용자가 바꾸게 열 것. CHITUBOX도 이 각도를 사용자에게 연다.)

이 한 각도가 적용되는 곳(기본 45° 기준):

1. **접점이 눕는 한계**: 접점이 표면 법선을 따라가더라도 **수평에서 이 각도보다 더 눕지 못하게** 잡는다. 너무 누우면 접점이 약해진다.
2. **경사 다리의 기울기**: 기둥이 옆으로 피해 갈 때(4-4) 그 다리가 이 각도로 내려간다.
3. **기둥끼리 잇는 지그재그 다리**: 좌굴 방지 연결(4-6)도 같은 각도.
4. **트리형으로 갈 때 가지가 모이는 원뿔각**(6장 트리형): 이것도 같은 각도.

**왜 하나의 파라미터로 묶나?** ① 각도가 하나뿐이라 구현·조정이 쉽고 사용자가 헷갈리지 않는다(값 하나만 만지면 전 구조에 일관 적용). ② 기본 45°는 레진에서 "받침 없이 스스로 버티는 경사"의 실무 한계에 가깝다 — 그보다 더 누우면 처진다. ③ **단, 특수한 형상이나 레진에 맞게 사용자가 40°·50° 등으로 조절할 수 있게 열어 둔다**(잠그지 않음).

> 조우현 확인 포인트: "꺾이는 각도"에 대한 답은 **구조 전체에 적용되는 각도 파라미터 하나(기본 45°, 사용자 조절 가능)**다. 접점이 눕는 것, 다리가 기우는 것 전부 이 한 값이 상한이며, 사용자가 그 값을 바꾸면 전 구조에 함께 반영된다.

### 4-4. 3단 폴백 — 바닥에 곧장 못 닿을 때

기둥이 수직으로 내려가는데 아래에 모델 본체가 가로막고 있으면 그냥 뚫을 수 없다. 순서대로 시도한다.

1. **1단 — 수직 하강**: 아래가 뚫려 있으면 그냥 곧장 바닥까지 내린다.
2. **2단 — 45° 경사 다리로 옆으로 피해 하강**: 장애물이 있으면 45°로 옆으로 비껴 내려가 빈 공간을 찾아 다시 수직 하강. 이 경사 다리에는 **최대 길이 제한**(약 15mm)이 있다 — 너무 길면 스스로 휜다.
3. **3단 — 모델 표면에 안착**: 그래도 바닥에 못 닿으면, **뒤집힌 화살촉 접점으로 모델의 다른 표면에 살짝 얹는다.** 단, 이렇게 모델에 얹는 가지에는 **실리는 총량 상한**(약 10mm 분량)을 둬서 모델에 과부하가 안 걸리게 한다.

**왜 3단인가?** 모든 점을 항상 바닥까지 곧게 내릴 수는 없다(복잡한 치아 형상). 곧게 → 비껴서 → 정 안 되면 모델에 얹기 순으로 물러서면 대부분의 형상을 처리할 수 있다.

### 4-5. 충돌 회피 — 모델을 관통하지 않게

기둥·다리가 내려가면서 **모델 본체를 뚫고 지나가면 안 된다**(뚫으면 출력물에 구멍/흠집).

- 정밀한 부피 계산 대신, **막대 둘레를 따라 광선(레이) 8~16개를 쏘고 안전거리 0.5mm를 둬서** 앞이 막혔는지 근사로 검사한다. 막혔으면 4-4의 폴백으로 피한다.
- 구현은 Babylon의 레이캐스트 기능이나 자체 충돌 구조를 쓸 수 있다(유승제 판단). **개념은 "굵은 막대를 몇 가닥 광선으로 근사해 앞을 살핀다"**는 것.

**왜 근사인가?** 완벽한 부피 충돌 검사는 느리고 무겁다. 광선 몇 개 + 여유 거리면 실용상 충분하다는 게 실증됐다.

### 4-6. 기둥끼리 연결 — 좌굴(휘어짐) 방지

가느다란 기둥이 높으면 혼자서는 옆으로 휜다(좌굴). 이웃 기둥과 이어 서로 버티게 한다.

| 기둥 높이 | 연결 규칙 |
|---|---|
| 15mm 이상 | 이웃 기둥 **1개**와 지그재그 다리로 연결 |
| 35mm 이상 | 이웃 **2개**와 지그재그/십자로 연결 |

연결 다리도 45°(4-3). **왜?** 높은 기둥일수록 잘 휘므로, 서로 손잡게 해서 하나의 틀처럼 버티게 한다.

### 4-7. 형상 선택 — 기둥형 먼저, 트리형 나중 (권고)

레진 서포트에는 두 가지 큰 형상이 있다.

- **기둥형(Default)**: 점마다 세운 세로 기둥 + 바닥까지의 경사 다리 + 기둥 상호 연결. 위에서 설명한 방식.
- **트리형(Branching/Tree)**: 위쪽 점들을 높은 것부터 45° 원뿔 안에서 **Y자로 계속 합쳐** 내려와, 아래로 갈수록 굵은 몇 개의 줄기로 모으는 방식. 재료가 덜 들고 떼기 쉽지만 알고리즘이 복잡하다.

**권고: 기둥형부터 만든다.**

- **왜?** 단순하고, 오픈소스로 검증됐고, **치과 모델(대체로 낮고 넓게 깔림)에는 기둥형으로 충분**하다. 트리형의 이점(높은 출력물에서 재료 절감)이 치과에서는 크지 않다.
- 트리형은 2차(후속)로 미룬다. 기둥형이 안정적으로 돌아간 뒤 검토한다.

## 5. 치과 특화 고려

우리는 치과용 상용 제품이다. 범용 수치를 그대로 쓰면 안 되고, 치과 실무값을 출발점으로 삼는다. (모두 실측 재검증 대상.)

- **작은 팁**: 치과 모델은 표면 정밀도가 중요해 **가는 접점**을 쓴다. 메인 서포트 top 반경 0.75~1.25mm / bottom 반경 1.0~1.8mm, 보조 서포트 top 반경 0.5~0.75mm 수준(Ackuretta 치과 가이드). ※ 이 수치는 **반지름 표기**이므로 지름으로 환산하면 2배임에 주의. 정밀 출력에서는 팁 지름을 0.10~0.3mm대까지 낮추기도 한다(Formlabs/AmeraLabs).
- **낮은 밀도**: 치과 모델은 대체로 낮고 넓어, 서포트를 너무 촘촘히 두면 자국·후처리가 늘어난다. **성기게(낮은 밀도)**가 기본.
- **래프트(raft) 필수**: 바닥판(래프트)을 깔아 기둥들을 안정시키고 플레이트에서 잘 떼도록 한다.
- **얇은 접점의 필요성**: 결국 치과에서 서포트 품질 = "얼마나 가늘게 붙여 자국을 줄이면서도 안 떨어지게 하느냐"의 균형이다. → 팁 지름별 버티는 한계를 우리가 **실측해야** 한다(9장).
- 참고: 클리어 얼라이너용 모델은 서포트 없이 **플랫 배치**가 관행이기도 하다(SprintRay). 서포트가 항상 정답은 아님.

## 6. UI 설계 방향

기존 v2 UI 규칙(치투박스 레퍼런스, light/medium/heavy 프리셋)과 이어진다. 상용 도구 공통 관례를 따른다.

### 4분절 파라미터

서포트를 **접점 — 연결부 — 기둥 — 바닥판** 네 구간으로 나눠 각각 조절한다(치투박스·라이치 공통 구성).

| 구간 | 노출할 값(예) |
|---|---|
| 접점(Tip/Contact) | 팁 지름, 침투 깊이(Contact Depth) |
| 연결부 | 서포트 구조 각도(기본 45°, 사용자 조절 0~90°, 4-3), 다리 최대 길이 |
| 기둥(Trunk) | 기둥 지름, 상호 연결(Cross Bracing) |
| 바닥판(Raft/Platform) | 래프트 두께, 리프트 높이 |
| 자동 배치(Auto) | **오버행 검출각**(3-1b, 출발점 30°), 밀도(%) |

> **미구현 보류(리드 결정 2026-07-20)**: CHITUBOX에는 **Small Pillar(가는 보조 기둥)**와 **Skate(바닥 발 모양)** 파라미터도 있으나, 1차 설계에서는 넣지 않는다. 메인 기둥+화살촉 접점이 안정된 뒤 필요해지면 후속 검토.

### 프리셋 — Light / Medium / Heavy

밀도·굵기 조합을 미리 묶은 3종. 사용자는 대부분 프리셋만 고르고, 고급 사용자만 4분절 값을 연다(라이치의 "프리셋 우선, 고급은 개방" 2단 UI). NanoSupport의 **small/medium/large 3분류**도 이 프리셋 발상과 같다(UI 아이디어만 참고).

**주의**: 현재 v2에도 light/medium/heavy 프리셋이 있으나, 그 프리셋이 조절하던 것은 "격자 간격" 등 폐기 대상 파라미터다(7장). 프리셋 이름은 유지하되, **조절 대상을 새 4분절 파라미터로 갈아끼운다.**

## 7. 현재 방식과 무엇이 근본적으로 다른가

`docs/진단_아일랜드서포트_20260715.md`가 밝힌 현재 v2의 실패 원인을 이 재설계가 어떻게 근본적으로 피하는지.

### 현재(v2)의 방식 — 전역 격자 필터링

현재는 **모델 전체에 4mm 간격 바둑판을 깔고, 그 교차점이 "우연히" 받쳐야 할 곳(아일랜드) 위에 떨어질 때만** 서포트를 만든다.

- **문제 1 — 아일랜드에 서포트가 안 붙음**: 치과 아일랜드(커스프)는 몇 mm²로 작아서 4mm 바둑판에 거의 안 걸린다 → 생성 0개. (실측: 반지름 0.5mm 아일랜드에 4mm 격자 → 0개.)
- **문제 2 — 대형 파일 멈춤**: 모델 전체에 격자를 깔고 매 교차점을 검사하니, 큰 파일에서는 검사할 점이 폭발해 멈춘다.

### 재설계의 방식 — 아일랜드에서 직접 샘플링

**받쳐야 할 곳(아일랜드·오버행)을 먼저 찾아서, 바로 거기에 점을 찍는다.** 격자를 깔고 "걸리길 기다리는" 방식이 아니다.

- **문제 1 해결**: 아일랜드를 검출한 다음 그 아일랜드 위에 직접 점을 찍으므로(크기별 3분기, 3-3), 아무리 작은 아일랜드도 반드시 최소 1점을 받는다. "우연"에 기대지 않는다.
- **문제 2 해결**: 모델 전체를 격자로 훑지 않고 **받칠 곳 주변만** 다루므로, 검사량이 "받칠 지점 수"에 비례한다. 대형 파일이라도 받칠 곳이 그만큼만 있으면 폭발하지 않는다.

**한 문장으로**: 격자를 깔고 걸리길 기다리는 방식(전역·수동적)을 버리고, 받칠 곳을 찾아가 직접 점을 찍는 방식(국소·능동적)으로 바꾸는 것 — 이것이 "아일랜드 실패"와 "대형 멈춤"을 동시에 푸는 이유다.

## 8. 구현 순서 제안 (유승제가 따라갈 단계 분할)

한 번에 다 만들지 말고, 아래 순서로 **작은 단계마다 눈으로 확인**하며 쌓는다. 각 단계에 "완료 판정" 기준을 둔다.

### 1단계 — 층 그래프 + 아일랜드/오버행 분류 (지현규 영역 접점)
- 슬라이스된 층 폴리곤을 아래→위로 훑어 아일랜드/오버행/반도를 분류한다.
- **기존 마진 찾기 알고리즘은 잠금 상태 — 건드리지 말 것**(`docs/references/feedback_margin_algorithm_lock.md`).
- **완료 판정**: 테스트 모델에서 아일랜드/오버행이 뷰어에 올바르게 표시된다(색으로 구분). 진단 문서의 "바닥 전체가 아일랜드로 검출됨" 버그가 재현되지 않는다.

### 2단계 — 서포트 점 생성 (점만 찍어 검증)
- 지지 반경 곡선(3-2) + 아일랜드 3분기(3-3)로 점을 찍는다.
- **아직 기둥을 세우지 말고, 점만 뷰어에 표시한다.**
- **완료 판정**: 작은 아일랜드에도 최소 1점이 찍힌다(진단 문서의 "0개" 재현 안 됨). 큰 파일에서 멈추지 않는다. 점의 위치·개수가 눈으로 타당하다.

### 3단계 — 구조물 생성 (유승제 주도)
- 점 목록을 받아 접점(4-1) + 기둥(4-2) + 45° 규칙(4-3) + 3단 폴백(4-4) + 충돌 회피(4-5) + 기둥 연결(4-6)으로 실제 기둥을 세운다. **기둥형만**(4-7).
- **완료 판정**: 모든 점에 기둥이 서고, 모델을 관통하지 않으며, 바닥/모델에 정상 안착한다. 뷰어에서 화살촉 접점 형상이 보인다.

### 4단계 — 바닥판/래프트 + 합성
- 기둥 발밑을 잇는 바닥판(래프트)을 깔고, 서포트를 모델과 함께 층별 슬라이스해 마스크/CTB에 합친다.
- **완료 판정**: Export한 결과(ZIP/CTB)에 서포트가 포함돼 실제 출력 데이터로 나온다(WORKFLOW 수동 검증 6번 계열).

### 5단계 — UI(4분절 + 프리셋) + 수동 편집 연동
- 4분절 파라미터 + 3프리셋 UI(6장). 사용자가 손으로 점을 추가/삭제하면 자동 밀도와 충돌 없이 어우러지게(수동 점은 주변 자동 밀도에 영향).
- **완료 판정**: 프리셋 전환 시 서포트가 눈에 띄게 바뀌고, 수동으로 점을 더하거나 지워도 다시 생성 시 반영된다.

## 9. 리드·유승제가 결정해야 할 것

이 설계를 구현으로 옮기기 전에 사람이 정해야 할 항목들이다. (연구 보고서 5건 + 이 설계에서 새로 생긴 것.)

| # | 결정 사항 | 배경/권고 |
|---|---|---|
| 1 | **기둥형부터 vs 트리형부터** | 권고: 기둥형 먼저(4-7). 단순·검증됨·치과에 충분. 트리형 2차. → 리드 확정 필요 |
| 2 | **치과 기본값 출발점** | 프루사 범용값(팁 0.4)에서 출발할지, Ackuretta 치과값(더 가는 팁)에서 출발할지. → 실측 실험 결과로 결정 |
| 3 | **접점 실험 계획** | "우리 레진·프린터로 팁 지름별 버티는 한계 길이"를 실측한 표가 있어야 3-3의 경계값·4-1의 팁 굵기를 정할 수 있다. **누가·언제·어떤 시편으로 실측할지** 계획 필요 |
| 4 | **disc 서포트(PR #19)와의 관계** | 기존 dental disc 서포트를 이 재설계가 **대체**하는지, **병존**(디스크 대량 출력용 별도 모드로 유지)하는지 |
| 5 | **top-down 특성 반영 시점** | 이 설계는 bottom-up 기준(전제 ②). 밀도 곡선·팁 강도의 top-down 실측 재조정을 **언제** 리드가 실기로 확인해 지시할지 |
| 6 | **성능(워커화) 편입 시점** | 마진/아일랜드 검출의 워커화(대형 파일 멈춤 해법, S-2)를 **이 재설계의 몇 단계에** 편입할지. 1단계 검출 재정비와 함께 갈지, 이후로 미룰지. 마진 로직은 잠금이므로 지현규 컨펌 필수 |
