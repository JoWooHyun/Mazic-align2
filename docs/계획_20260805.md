1. **서포트 분담 이관의 팀 통보** — "서포트 다 내 쪽으로"를 로드맵·메모리에 기록하고 S-4b를 AI dev-cycle로 진행했습니다.

   결정이라, **유승제에게 리드가 직접 통보**해야 합니다. 유승제가 이미 작업 중이면 충돌 위험.
2. **CHITUBOX 원본 STL 미사용** — B안은 유지하되, 리포에 커밋하는 부품은 **자체 생성 STL**(같은 단위 규격)로
   했습니다. 이유: 상용 제품 리포에 타사 소프트웨어의 리소스 파일을 재배포하는 형태가 되는 위험 회피.
   기존 "라이선스 무관" 결론은 '단순 도형 사용'에 대한 것이었고, '원본 파일 재배포'는 별개 문제라 판단했습니다.
   원본을 쓰고 싶으시면 parts/ 폴더의 파일만 교체하면 됩니다 (같은 규격 — 코드 무변경).
3. **회전된 STL 케이스 수정 방식** — 검수에서 "STL이 회전된 상태면 기둥이 기울어짐" 결함이 나와,
   월드 기준 수직 조립 후 로컬화하는 방식으로 수정했습니다 (기둥은 항상 월드 수직). 설계 의도와 일치하는지 확인 요망.
4. **화살촉 목 지름 근사** — 원뿔 꼭짓점을 앞구슬 중심에 두는 조립이라 접합부 목이 팁보다 약간 가늘어지는
   근사입니다 (검수 통과 범위). 실측 검증 때 실물로 확인 필요.
5. **생성 버튼이 디버그 오버레이(마젠타/파랑 점)도 함께 표시** — 생성 후 오버레이 자동 정리 여부는 취향 문제라
   그대로 뒀습니다. 정리 원하시면 소소 수정.
6. **프루사 기본기능 우선순위** — 자동배치 → 수치패널 → Place on face 순으로 제안(2장 B-1). 착수 지시 필요.
7. **dev-cycle 역할 모델 문서 반영** — WORKFLOW.md·reviewer.md(model: fable)·dev-cycle.md를 새 체제로
   수정했습니다. 의도와 다르면 되돌리기 쉬움.
8. **PR 처리** — 재검수 통과 시 PR을 열어 두겠습니다(머지는 리드 권한 — 승인 체제 유지).
