   ※ `utils/transform.ts`는 Babylon을 import해서 헤드리스 검증이 불가 → **types 쪽에 두는 게 정답**(구현 시 확인됨).

   **기존 transform undo entry 안에** 복원(addSupports)/재삭제(redo)를 넣어 Ctrl+Z 1회로 동시 복원.
   기존 world 서포트(trunk/bridge/manual) 패치·follow 로직은 무변경.

### B-1 검수 지시 (reviewer에게 그대로 전달)

수용 기준 1~4 재실행 + 아래 특별 검토 A~F 판정 → 최종 PASS/FAIL.

- **A. undo id 재사용 (가장 중요)**: undo의 `addSupports(삭제 전 객체)`가 같은 id로 재삽입될 때
  **IndexedDB 레포(`repo.addSupports`) 구현이 이를 허용하는지 코드를 직접 열어 확인**(put vs add).
  실패하면 Ctrl+Z가 조용히 깨진다. — coder가 미확인이라 표명한 지점.

- **D. B-11 continue의 안전성**: XZ 드래그 종료 후 stl-local parent 유지 / world는 기존대로 해제 /
  onDragStart의 setParent(mesh)와 정합(이미 parent면 no-op인지).
- **E. 안내 배너**: 5초 타이머 정리(언마운트·연속 발생 리셋) / 삭제 0개면 배너 안 띄우는지.

### 만들 것

1. **3단 폴백** — 프루사 실소스 정독 결과 **0단이 하나 더 있다**:
   `근처 기둥에 다리 합류` → `수직 하강` → `경사 다리로 걸어나가기(45°)` → `모델 표면 앵커` → `실패 시 무효화+통지`
2. **충돌 회피** — 막대 둘레 링 광선 8개(접점 주변 16개) + 안전거리 0.5mm.
   **내부 시작 처리 필수**: 광선 시작점이 메시 내부면 관통 후 재발사 (화살촉 0.2mm 침투 전제).
3. **기둥 연결** — 높이 15mm↑ 이웃 1개 / 35mm↑ 2개, zstep=tan(45°) 지그재그, 다리마다 충돌검사, 높이비 50% 규칙.
4. **기둥 공유 (B-3 해소책)** — ⚠️ **프루사는 점마다 기둥을 세우지 않는다.** 지면 직행 가능한 점들을
   클러스터로 묶어 중심 1개만 기둥 + 나머지는 경사 다리 합류. **현재 서포트 1,300개 문제의 정공법.**
5. **꺾임점마다 구(Junction) 삽입** — 다리·기둥 접합 단면 연속성 (S-4b-1 파단 이슈의 일반해).
6. **중복점 제거** — 0.1mm 이내 점 제거 (프루사 전처리).

### 제약

- 형상 = **B안(부품 STL 조립)** 유지. `assemble-core.ts`에 "임의 두 점을 잇는 막대" 조립 추가.
