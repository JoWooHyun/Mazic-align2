## 2. 주요 작업 내역

### ① 서포트 기둥 생성 1차 완성 (S-4b-1) — PR #39

- **방식 확정**: 부품 STL을 조립하는 CHITUBOX 방식(B안). 헤드리스 실증으로
  "STL 조립물이 CTB까지 정상 출력되는가"라는 유일한 미확인점을 해소한 뒤 채택.
- 화살촉 접점(앞구슬+원뿔+뒷구슬, 0.2mm 침투) + 수직 기둥 + 바닥 발 구현.
- 부품 STL은 **자체 제작**(CHITUBOX 원본 미사용 — 재배포 문제 회피).
- 남은 범위: 3단 폴백·충돌 회피·기둥 연결·기둥 공유 → **다음 작업(S-4b-2)**

### ② 출력 품질 치명적 결함 수정 (B-7) — PR #40

- **현상**: 서포트와 모델이 겹치는 부위가 마스크에서 **구멍(미경화)** 으로 뚫림.
- **원인**: 래스터화가 even-odd 방식이라 서로 다른 솔리드의 겹침이 상쇄(XOR)됨.
  화살촉이 모델에 0.2mm 파고드는 것이 설계 전제라, **서포트 방식 전체의 성립 조건**이었다.
- **2차 원인**: STL 로더의 축 스왑으로 모델 감김 방향이 뒤집혀 있었음 → 자동 정규화 추가.
- 자동 검증 6케이스를 **전부 통과하고도 실물에서만 드러난** 사례.

### ③ 서포트 무효화 정책 수립 (B-1·B-11) — PR #43

- **문제**: 서포트를 만든 뒤 모델을 회전하면 기둥이 함께 기울어 출력 불가.
- **정책 확정(리드)**: CHITUBOX식 무효화 — 삭제 + 사용자 안내.
  단 **수평 이동은 예외로 유지**(기둥 수직성·바닥 접지가 보존되어 기하학적으로 유효).
- Ctrl+Z 한 번으로 모델 변형과 서포트가 함께 복원되도록 undo 통합.

### ④ 뷰어 조작 정상화 (B-9·B-12·B-13·B-14) — PR #42·#44·#45·#47

리드가 **CHITUBOX 실물과 화면을 나란히 놓고 대조**해 문제를 제기 → 전부 수정.

| 문제 | 수정 |
|---|---|
| 회전 시 모델이 제자리가 아닌 **공전** | 회전 피벗을 바운딩박스 중심으로 |
| 회전하면 기즈모 축이 함께 기울어짐 | world 축 고정 (구 버전에 있던 설정이 누락된 **회귀**였음) |
| 회전하면 좌표값이 따라 변함 | 표시 기준을 모델 중심으로 환산 (내부 저장값은 불변) |
| 높이축이 Y로 표기 (프린터 관례는 Z) | 표시 레이어만 Z-up 환산 (내부 좌표계는 유지) |
| 수치 입력칸 전반 오작동 | Enter/blur 커밋형으로 전환 (5개 패널 일괄) |

### ⑤ 기술 조사

- **프루사 SLA 서포트 소스 전문 정독** — 다음 작업(S-4b-2)의 클린룸 스펙 확보.
  핵심 발견: 프루사는 **점마다 기둥을 세우지 않고** 클러스터 중심에 1개만 세운 뒤 나머지를
  경사 다리로 합류시킨다 → **현재 서포트 1,300개 과다 문제의 정공법.**
- ⚠️ 프루사는 AGPL이므로 **개념만 참고, 코드 이식 금지** 원칙 유지.

## 3. 이번 주에 확립된 개발 방식

### 실물 확인 없이는 완료로 보지 않는다

**B-7이 자동 검증 6케이스를 전부 통과하고도 실물에서 결함이 드러났다.**
자동 검증은 정상 입력만 테스트하기 쉽다 — 실물 확인을 대체할 수 없다.
이후 모든 작업에 "리드 실물 확인 포인트"를 PR에 명시하는 절차를 넣었다.

### 검증 스크립트에 대조군을 넣는다

수정 후 통과만 확인하면 "그 스크립트가 실제로 버그를 잡는지"를 알 수 없다.
→ **수정 전 구현을 함께 돌려 실패하는 것까지 확인**하는 방식을 규약으로 확립.

이 규약이 실제로 3번 연속 결함을 잡아냈다:

| 사례 | 대조군이 없었다면 |
|---|---|
| 서포트 무효화 | 회전 직후 Ctrl+Z 시 서포트가 **전부 소실**되는 결함을 놓쳤을 것 |
| POSITION 표시 | 슬라이더를 **끄는 동안** 좌표가 14mm 흔들리는 결함을 놓쳤을 것 |
| 축 표기 | 회전 환산식이 **단축에서는 우연히 맞고 복합 회전에서만 틀리는** 오류를 놓쳤을 것 |

### 계획 단계의 오류도 구현 중에 잡힌다

축 표기 작업에서 **계획서에 적힌 회전 환산식이 틀렸음**을 구현 중 발견해 바로잡았다
(성분 교환 → 쿼터니언 켤레). 단축 회전에서는 우연히 정확히 일치해 발견이 어려운 종류였다.
